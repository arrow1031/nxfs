```
python gh\ghctl.py status                                    # 账号 / 额度 / 相关仓库
python gh\ghctl.py runs arrow1031/nxfs-impl --steps           # CI 结论
python gh\ghctl.py submodule-bump nxfs-impl --commit --push   # 子仓推送后更新父仓指针
```

**子仓改动固定流程**：先在子仓提交推送 → `submodule-bump` 更新父仓 gitlink → 推父仓。

## 上下文纪律（真正的成本杠杆）

1. **一个任务一个会话**；任务完成即归档开新会话——避免上下文无限增长被反复重发。
2. **不要并发两个长会话共用同一份付费额度**（实测已发生）。
3. **长会话中途切到付费模型是最贵组合**：大上下文 × 付费单价。要切换就**先开新会话**，让上下文从零开始。
4. **读文件用 grep 定位 + 只读所需片段**，不整读大文件（`nxfs.h` 71 KB、`index.d.ts` 57 KB；整读一次，之后每回合都在为它付费）。
5. **验证输出只取结论行**（`Select-Object -Last 3`），不 dump 全文。
6. **隔离任务交给子代理**（独立小上下文），不要塞进主会话。

## 降级规则（只在失败时用）

```
限流 429（速率） → 稍后重试，或换 provider：zhipu → nova-1 → nova-2 → deepseek-flash
余额不足 429     → 该模型已不可用，直接切 deepseek-flash（不要重试）
```

## 禁止事项

- ⛔ 用 `glm-5.3-flashx` 跑分析类长会话（2 倍价买 2.5 倍速，对长上下文零收益）
- ⛔ 把付费模型设为默认路由或会话默认模型
- ⛔ 在同一会话里反复整读同一大文件
- ⛔ 在同一份额度上并发多个长会话

## 额度充值后的建议用法

充值后**不要**恢复成会话默认。正确用法是：平时一律 `deepseek-flash`，
遇到真正的硬难题时**新开一个短会话**专门问它，问完即弃。
