## 边界（先看这段）

**需要读**：`10-公共约定.md` §8（保留名、8 字节对齐）；`80` 的转译接口。

**不需要读**：EFI 驱动、NAND、块分配内部细节。

**本包不做**：不做任何文件系统逻辑。它是**薄适配层**：
把 Windows 的请求翻译成 `80` 的调用，把结果翻译回 Windows。

### ⚠️ 许可证边界（本包最容易踩的合规坑）

| 组件 | 许可证 | 后果 |
| :--- | :--- | :--- |
| WinFsp | GPLv3 + FLOSS 例外 / 商业双授权 | 用其 FLOSS 例外则**整个驱动必须开源**；要闭源须买商业授权 |
| Dokany | LGPL | 动态链接可闭源，静态链接有义务 |

**纪律**：本包与核心之间必须是**进程边界**（IPC），不是链接边界。
核心（可闭源）通过 IPC 提供服务，适配层作为独立进程加载 WinFsp/Dokany。
**不要**把核心静态链进适配层——那会把核心代码拖进 GPL/LGPL 义务。

## 职责

| 职责 | 说明 |
| :--- | :--- |
| 挂载 / 卸载 | 盘符或目录挂载点 |

## 关键设计点

### 1. 语义映射表（Win32 ↔ NXFS）

| Win32 | NXFS | 注意点 |
| :--- | :--- | :--- |
| `CreateFile` | `file_open` | `FILE_SHARE_*` ↔ `NXFS_SHARE_*`（4 个值一一对应，`NXFS_SHARE_ALL = 7`） |
| `ReadFile` / `WriteFile` | `file_read` / `file_write` | 段模型（`base` + `offset`）可直接映射 |
| `GetFileInformationByHandle` | `file_get_attr` | `ntfs_attrs` **裸透传**，不做解释 |
| `FindFirstFile` / `FindNextFile` | `dir_enum` + `nxfs_cursor_t` | 游标由调用方持有；**不要**在适配层维护隐式遍历状态 |
| `MoveFileEx` | `dir_rename` | `on_conflict` ↔ `MOVEFILE_REPLACE_EXISTING` |
| `DeviceIoControl` | `file_ioctl` | 操作码命名空间需按 GUID 划分 |
| `DeleteFile` | `dir_remove` | 即时回报（`70` 的标记式删除），**不要**等后台回收 |
| `FlushFileBuffers` | `volume_flush(sync=1)` | |

### 2. 打开语义的标志映射

| Win32 组合 | NXFS |
| :--- | :--- |
| `OPEN_EXISTING` | `flags = NONE` |
| `OPEN_ALWAYS` | `flags = CREATE` |
| `CREATE_ALWAYS` | `flags = CREATE\|TRUNCATE` |
| `CREATE_NEW` | `flags = CREATE\|EXCLUSIVE` |
| `TRUNCATE_EXISTING` | `flags = TRUNCATE` |
| 目录打开 | `flags \|= NXFS_FILE_FLAG_DIRECTORY` |
| 不跟随重解析点 | `flags \|= NXFS_FILE_FLAG_NO_FOLLOW` |

**注意**：`NXFS_FILE_FLAG_CREATE` 与 `NXFS_FILE_FLAG_DIRECTORY` **共用同一位置位**
（都是 `1 << 0`）。这意味着"创建目录"要另用 API（`dir_create`），
不能靠 `file_open` + `DIRECTORY` 表达创建。这是 `nxfs.h` 的既有约定。

### 3. 保留设备名必须在**路径校验层**拦截

Windows 保留名（`CON`/`PRN`/`AUX`/`NUL`/`COM1`–`COM9`/`LPT1`–`LPT9`，
**含带扩展名形式**如 `NUL.txt`）必须在进入核心之前就拦掉。

**为什么在适配层拦**：核心面向多平台，不应内置 Windows 特有规则。
但保留名清单在 `10-公共约定` §8 已列为强制项 —— 两处都要有：
适配层拦（给 Windows 用），核心也拦（防止通过 IPC 绕过）。

### 4. 大小写语义

| 能力 | 说明 |
| :--- | :--- |
| `NXFS_CAP_CASE_INSENSITIVE` | 查找不区分大小写 |
| `NXFS_CAP_CASE_PRESERVING` | **但保留原始大小写**（NTFS 行为） |

**两者要同时具备**才是 NTFS 兼容行为。只做不区分大小写会丢失原始名，
只做区分大小写则与 Windows 应用不兼容。

挂载时用 `NXFS_MOUNT_CASE_INSENSITIVE` / `NXFS_FEATURE_CASE_INSENSITIVE` 表达。

### 5. 路径编码：WTF-8 是硬要求

Windows 文件名可以包含**未配对代理对**（NTFS 允许多种字节序列）。
因此：

- 适配层从 `UNICODE_STRING` 转字节时必须用 **WTF-8**，不能用严格 UTF-8 编码器
  （严格编码器会拒绝未配对代理对）。
- 核心的路径校验**不得**在 UTF-8 校验阶段拒绝这类名称（`10-公共约定` `INV-9`）。

**这是最容易在联调时才发现的兼容性事故**：本机测试用普通 ASCII 名一切正常，
用户拿一个从 NTFS 拷贝来的文件名就崩。

### 6. 路径分隔符与规范化

- Windows 用 `\`，NXFS 用 `/` → 适配层转换。
- 但**不要**在适配层做 `..` 解析（那是核心的路径规范化职责），
  否则两边解析结果可能不一致。适配层只做分隔符替换 + 保留名检查。

### 7. 分区可见性（`§2.4`）

- 用 `10-公共约定` §3 的 MBR `0x7F` / GPT 自定义 GUID。
- **绝不要**用 `0x8E`（Linux LVM）或 Microsoft 基本数据 GUID —— 前者会被 Linux 误认，
  后者会被 Windows 自动挂载并**提示格式化**（用户误点即丢数据）。

### 8. 缓存策略：不要另建缓存

- 元数据缓存由 `80` 负责；文件数据缓存交给 Windows 自身的 Cache Manager。
- 适配层**只做转译**。若在适配层再加一层元数据缓存，就会出现
  "两个缓存各自失效"的问题，且 `80` 的世代号机制无法覆盖它。

## 接口（本包消费的 `nxfs.h` 部分）

取决于选用的适配框架，本包**不新增** `nxfs.h` 符号，只消费：

| 消费项 | 用途 |
| :--- | :--- |
| `file_open` / `file_read` / `file_write` / `file_close` | 文件 IO |
| `file_get_attr` / `file_set_attr` | 属性 |
| `dir_enum` + `nxfs_cursor_t` | 目录遍历 |
| `dir_create` / `dir_remove` / `dir_rename` / `dir_link` | 目录操作 |
| `volume_flush` | 刷新 |
| `nxfs_access_t` / `nxfs_share_t` / `nxfs_file_flag_t` | 语义映射 |
| `nxfs_file_attrs_t.ntfs_attrs` | 裸透传 |
| `NXFS_CAP_CASE_INSENSITIVE` / `CASE_PRESERVING` | 大小写 |

## 常见坑

1. **许可证边界** —— 不要静态链接 WinFsp/Dokany 进核心。
2. **`NUL.txt` 这类带扩展名的保留名**也要拦（只拦裸名是常见漏项）。
3. **WTF-8**：别用严格 UTF-8 编码器转换 Windows 文件名。
4. **`CREATE` 与 `DIRECTORY` 共用位**，创建目录要用 `dir_create`。
5. **不要在适配层解析 `..`**，交给核心。
6. **不要另建元数据缓存**。
7. **`FindNextFile` 的隐式句柄状态**是 Win32 逼出来的，但核心游标必须由调用方持有。
8. **GUID 用 `0x7F` / `13 07 3c 46-…`**，不要用 `0x8E` 或基本数据 GUID。
9. `NXFS_SHARE_ALL` 是 **7**（三个位全置），不是"无限制"的神奇值。
