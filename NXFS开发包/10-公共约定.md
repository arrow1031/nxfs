# 10 · 公共约定（全局必读）

> 本文件是**唯一全局必读**文档。所有块开发包引用此处定义，**不重复定义**。
> 修改全局约束只改本文件——这是控制 Token 膨胀的关键规则。

---

## 1. 术语与命名

**两组"层"含义不同，严禁混称**（混称会同时导致深度上限设错与层间对应表出错）：

| 称谓 | 含义 | 取值 |
| :--- | :--- | :--- |
| **契约层** | API 调用契约分层 | L0 介质 / L1 原语 / L2 契约 / L3 数据面 / L4 安全路径 |
| **数据层** | 日志区的数据分层 | 顶层（根层） / 中间层 / 底层 |

**"深度"一律指契约层的调用/结构深度**，上限 16；数据层固定 3 层，与深度无关。

**责任主体（Subject）**：缓存一致性的最小权威粒度。任何缓存条目的有效性只由
`(kind, a, b) + 世代号` 决定，**不由卷级或全局事务号决定**。见 §6。

## 2. 单位与编码（全部强制）

| 对象 | 约定 |
| :--- | :--- |
| 路径 | UTF-8 字节串 + **显式长度**，**非** NUL 终止 |
| 文件名编码 | 必须支持 **WTF-8**（含未配对代理对），以完整兼容 NTFS 文件名 |
| 时间 | 纳秒，`int64`，Unix epoch |
| 容量 | 字节，`uint64` |
| 偏移 | **簇号**，`uint32`；区间为半开 `[start, start + count)` |
| 比例 | **万分比整数** 0–10000（禁止浮点——跨平台舍入差异会让阈值不可复现） |
| LBA | 扇区为单位（仅安全路径与坏道报告使用），`uint64` |

## 3. 规范常量（编译期可核对，禁止硬编码副本）

```c
#define NXFS_SAFEPATH_IO_TIMEOUT_MS 100u   /* 硬性，超时即错误返回 */
#define NXFS_SAFEPATH_MAX_DEPTH     16u    /* 调用/结构深度 */
#define NXFS_SAFEPATH_EVENT_SIZE    64u    /* 定长事件记录 */
#define NXFS_RING_SLOT_SIZE         4096u  /* 整页 */
#define NXFS_RING_SLOT_HEADER_SIZE  128u
#define NXFS_RING_PAYLOAD_MAX       3968u  /* 4096 - 128 */
#define NXFS_PATH_MAX_BYTES         32768u
#define NXFS_NAME_MAX_BYTES         255u
```

### 磁盘格式常量

| 项 | 值 |
| :--- | :--- |
| 簇大小 | 4096 B（可配置 16384 / 65536） |
| 每簇头部 | CRC32C 校验和（CPU 计算，存储层只搬簇，不解释） |
| 索引条目宽度 | **8 B** = 4B 簇号 + 2B 长度 + 1B 状态 + 1B 校验 |
| 兼容区 | 32–64 MB，仅承担传统 BIOS 引导与引导配置 |
| 主总账 | 64–256 KB，分区头 |
| 副总账 | 分区中部，结构与主总账相同 |
| 跨文件区 | 256 MB–1 GB |
| 引导文件表 | 固定 **4** 个条目 |

### 分区标识（**不要改，尤其不要用 0x8E**）

| 项 | 值 | 理由 |
| :--- | :--- | :--- |
| MBR 类型字节 | **`0x7F`** | `0x8E` 是 **Linux LVM**，会让 Linux 侧探测逻辑误认并触发自动激活 |
| GPT 类型 GUID | **`13073c46-c0da-4696-817f-6d12902515e3`** | 随机 v4；不能用 Microsoft 基本数据 GUID（会被 Windows 提示格式化） |

取证依据：util-linux 2.42.3 `include/pt-mbr-partnames.h` / `pt-gpt-partnames.h`。

### 策略参数

| 项 | 值 |
| :--- | :--- |
| 检查点间隔 | 30–60 min；日志总量超分区容量 **1%** 时强制 |
| 紧急空闲空间 | **5%**，冷数据/常规写入不得占用 |
| 预留回收触发 | 预留浪费率 > **30%** |
| 古旧文件定义 | > 6 个月未修改 **且** 预留使用率 < 20% |
| 日志区隔离带 | 子文件夹日志区之间 **≥ 1 簇** |
| 块内间隔 | 1–2 簇缓冲带 |
| 程序文件大文件阈值 | **> 64 MB 独立成块** |
| 日志量基线（1000 文件夹） | 顶层 ~64 KB / 中间 ~3.2 MB / 底层 ~115 MB |

## 4. 错误码使用纪律

错误码全表见 `nxfs.h`（负值域）。此处只规定**必须遵守的三条纪律**：

### 纪律一：三种"失败"必须区分，绝不合并

| 结果类别 | 正确处置 | 用码 |
| :--- | :--- | :--- |
| 数据未写入 | **可重试** | `NXFS_ERR_TIMEOUT` 等通用码 |
| 数据可能写了一半 | 靠 CRC32C 识别并丢弃 | `NXFS_ERR_CORRUPT` |
| **数据已写入、完整性不确定** | **不可重试**（重试会制造第二次不确定），必须靠 CRC32C 事后核验 + 降级链 | `NXFS_ERR_INTEGRITY_UNCERTAIN` / `NXFS_ERR_SAFEPATH_APPEND_UNCERTAIN` |

第三类是"主总账校验和不过 → 走副总账"这条恢复路径的**具体成因**，因此必须独立成码。

### 纪律二：快速重试必须声明，不得沉默

安全路径 `sector_write` 失败后允许**一次最快最小重试**，但：

- 重试成功后返回 `NXFS_ERR_SAFEPATH_QUICK_RETRY_DONE` 并置
  `quick_retry_done = 1` —— 明确告知调用方"**写已成功（经重试）**"；
- **防双写铁律**：除"两次均失败"外，调用方在任何非 NXFS_OK 返回下
  **不得重发同一写请求**（重发会造成双写）；
- 最小重试 = 剥除一切可选环节（无分配、无日志、无状态机），只做那一次必要的扇区写；
- **不得成为可关闭选项**（允许关闭就等于让"重试策略"进入安全路径，违反分层原则）。

完整返回值表见 API v1.0.1 `nxfs.h` 的 `sector_write` 文档与
`fs-api-design/兼容层适配报告.md`。

### 纪律三：降级必须可见

能力位请求后若不支持，必须回报被忽略的位（`features_ignored`）。静默降级不允许。

## 5. 分层不变量（违反即为设计错误）

| ID | 不变量 |
| :--- | :--- |
| `INV-1` | **安全路径（L4）不做策略**：只暴露扇区读写、CRC32C、总账解析、引导表解析、内核读取、事件追加。需要策略或分配的操作一律返回 `NXFS_ERR_SAFEPATH_FORBIDDEN` |
| `INV-2` | **安全路径零动态分配**：所有缓冲区由调用方提供，不链接分配器 |
| `INV-3` | **安全路径状态在调用方**。唯一例外是 `event_append`，且必须在头文件中显式标注为例外 |
| `INV-4` | **存储抽象层只搬簇，不解释簇内容**。CRC32C 由 CPU 计算，存储层不解析元数据 |
| `INV-5` | **L4 与 L2 边界分离但语义对应**：L4 写入的数据 L2 必须能正确读取，反之亦然 |
| `INV-6` | **可引导卷上，引导文件表所指文件豁免物理迁移**（卷级不变量，非调用方可选项）。理由：否则冷启动阶段一按总账 LBA 直读会读到已蒸发或复用的块 |
| `INV-7` | **实现能力 ≠ 卷属性**：`NXFS_CAP_BOOT`（此实现具备引导能力）与 `NXFS_VOLATTR_BOOTABLE`（此卷可引导，挂载时探测）不可混用 |
| `INV-8` | **紧急保留空间不被常规写入占用**，仅用于避免"缺口不可见" |
| `INV-9` | **禁止在 UTF-8 校验阶段拒绝合法卷内名称**（必须支持 WTF-8） |
| `INV-10` | **索引条目按簇对齐** |

## 6. 责任主体与缓存一致性（跨多块，故置于公共约定）

### 六类主体划分

| 被缓存的事实 | kind | `a` | `b` |
| :--- | :--- | :--- | :--- |
| 文件元数据 / inode / 簇映射 | `FILE` | FileId | 0 |
| 目录列表 / 子文件夹偏移 | `FOLDER_LOG` | FolderId | 0 |
| 类型标记（普通/程序） | `PARENT_LOG_ENTRY` | FolderId | 条目下标 |
| 块空闲池、extent 归属、预留量 | `EXTENT` | 起始簇 | 簇数 |
| 坏的 / 待处理扇区 | `BAD_SECTOR_SHARD` | 分片号 | 0 |
| 跨文件区条目 | `CROSSFILE_ENTRY` | 条目序号 | 0 |
| 延后完成事件（安全路径登记） | `DEFERRED_EVENT` | 受影响位置（v1：LBA） | 受影响扇数（v1） |

辅助：`VOLUME`（仅限挂载/卸载等**整卷结构变更**，**不可**用于常规变更）。
上表为 `a`/`b` 语义的**唯一权威**（与 API v1.0.1 `nxfs_subject_t` 注释一致）；
安全路径兼容层的登记实现已按 `DEFERRED_EVENT` 行执行。

**不设主体**：空间水位、紧急保留量 —— 必须全局精确，不可缓存。

### 世代号规则

- 世代号**只在权威性变更时递增**，0 为非法值。
- 校验是**版本比较**，不是匹配清单。因此失效通知**幂等、可丢失、可乱序、可重放**：
  漏收一条不会造成永久陈旧，收到重复也无副作用。
- **变更类操作必须回传受影响主体集合**（`affected`）。缺少它，调用方只能保守地大面积
  丢弃缓存，"最小责任主体"就白设计了。

### 主体冻结（升降层专用）

| 状态 | 语义 |
| :--- | :--- |
| `ACTIVE` | 可读写，缓存可直接信任 |
| `FROZEN` | **拒绝新写入**（返回 `NXFS_ERR_SUBJECT_FROZEN`），缓存按映射转换或丢弃 |
| `CONVERTING` | 预算内增量转换，**可中断续作** |
| `DEAD` | 必须整体丢弃 |

**冻结后不得静默接受新写入**——否则会出现两个都"看起来有效"的主体，这是最坏情况。

### 移交裁定（两条容易搞错）

| 规则 | 说明 |
| :--- | :--- |
| 资格与执行解耦 | 进度越过半数是**资格**，窗口边界才是**执行时机**；世代号在**移交完成时**递增，**不在越线时**递增 |
| 空窗口完全无操作 | 不递增任何世代、不产生任何失效。否则每个窗口边界都造成无意义的缓存失效风暴 |
| 权威不对称 | 目标侧"已确认接收"是**完整证明**；源侧记录只是**辅证**，能补强、**不能否证** |

## 7. 提交与可见性（数据面）

```c
typedef enum nxfs_slot_state {
    NXFS_SLOT_FREE = 0x00, NXFS_SLOT_WRITING = 0x01,
    NXFS_SLOT_COMMITTED = 0x02, NXFS_SLOT_ACKED = 0x03,
    NXFS_SLOT_ABORTED = 0xFE
} nxfs_slot_state_t;
```

**三条硬规则**：

1. **只有 `COMMITTED` 的槽位可见**；之前的内容一律不可读——这不是优化，是防止读到撕裂的元数据。
2. 生产者以 **release** 语义发布 `COMMITTED`，消费者以 **acquire** 语义读取。
3. `acked_seq` **可跳跃**（是"已确认的最高序号"，不是连续确认数）——批量提交允许乱序完成。

**缓存只缓存已提交事务的元数据**（设计稿 §6.4）。卷的 `mounted_at_seq` 是全局基准点，
用于判断"整体视图是否过时到需要重整"，**不用于逐个条目校验**（那是世代号的职责）。

## 8. 兼容性机制（跨块强制）

| 机制 | 做法 |
| :--- | :--- |
| 结构体版本化 | 首字段 `struct_size`；只允许**尾部追加**字段，禁止改序 / 改宽 / 复用保留字段 |
| 函数指针表 | 只导出 2 个符号；v1/v2 可在同进程共存 |
| 能力位 | 位域；**未知位必须被忽略** |
| **位域宽度** | **所有位族最高位必须 ≤ 31**（C 侧静态断言 + `verify/consistency_check.py` 双风格核对）。理由：绑定层 JS 位运算强制 32 位，超过则"未知位忽略"承诺会**静默失效**。确需 bit ≥ 32 时，绑定层必须改用 bigint |
| 8 字节对齐 | 跨 ABI 边界结构体一律 `NXFS_ALIGN8` |
| 命名 | 全部符号加 `nxfs_` / `NXFS_` 前缀 |
| 保留名 | 必须拦截 Windows 设备名（`CON`/`PRN`/`AUX`/`NUL`/`COM1-9`/`LPT1-9`，含带扩展名形式）与 NTFS 元数据名（`$MFT`/`$LogFile`/`$Bitmap`/`$Boot`/`$UpCase`/`$Extend`） |

> 为什么强制 8 字节对齐：同一结构体在 System V AMD64 与 MSVC/Windows x64 下
> `_Alignof` 可能不同（例如成员最大仅 4 字节时前者给 4、后者给 8），导致共享内存
> 结构体数组**静默错位**。NXFS 编写期已实际踩过（`nxfs_safe_io_result_t`）。

## 11. 总开发期与环节

> **命名规则**：**期**（一期 / 二期）是最高层；**环节**是子开发级别；
> **阶段**另有用途，不表示开发进度（见下）。

| 期 | 内容 | 状态 |
| :--- | :--- | :--- |
| **一期** | **机械盘侧全部开发**（`20`～`B0` 共 10 个包） | 🚧 当前进行中 |
| **二期** | **NAND 相关全部功能**（设计稿 §十五 + 包 `C0`） | ⏸️ 已冻结，待一期可用后开启 |

| 环节 | 内容 |
| :--- | :--- |
| **一期 · 环节1** | 只读最小可跑：`20` → `30` → `40`(只读) |
| **一期 · 环节2** | 写入路径：`40`(CoW) → `50` → `70` → `60` |
| **一期 · 环节3** | 集成与优化：`80` → `A0` → `90` → `B0` |
| **二期 · 环节1** | NAND 缓存（冻结） |

> ⚠️ **"阶段"不表示开发进度**，它在本文档中专指另外两件事：
> `B0` 的**三阶段引导流程**（UEFI 固件 → 内核初始化 → 高级驱动）、
> 以及 `60` 的**四个动作步状态机**（待分发 → 分发中 → 转移完成 → 回收）。
> 不要用"阶段"表示子开发。

**NAND 冻结范围（一个都不做）**：设计稿 §十五、模块表中的"NAND 缓存层"与存储抽象层
的"NAND 缓存管理"职责、API 中三个 NAND 能力位（`NXFS_CAP_NAND_CACHE` /
`NXFS_VOLATTR_HAS_NAND_CACHE` / `NXFS_FEATURE_NAND_CACHE`）、开发包 `C0`。

## 14. 跨包依赖权属（一个源只有一个所有者）

各包要"按权责独立、又能互相调用"，前提是**依赖关系显式且不重复**。本节是强制规则。

### 14.1 三分法：`sources` / `link_only` / `includes`

| 声明 | 含义 | 纪律 |
| :--- | :--- | :--- |
| `sources` | **本包自有**、进本包编译与扫描清单的源 | 只能写**本包目录内的裸文件名**（不得含路径分隔符） |
| `link_only` | 依赖的源：本包测试要真跑它，但它不属于本包交付面 | 写成 `<包目录>/<文件>`（该文件必须真在对方 `sources` 里），**或** `verify/<设施>/<文件>`（**共享工程设施源**——不属于任何实现包，故没有所有者可查；存在性由 `check_deps.py` 单独校验） |
| `includes` | 依赖的**头文件**搜索路径（只加 `-I`） | 直接 include 对方冻结头，**不自建副本** |

### 14.2 三条不许

1. **不许复制副本。** 不要在 `40` 里再放一份 `storage.c` —— 宁可用 `link_only` 指过去。
   包级测试各自成二进制，**看不出**两个包重复编译同一个源；一旦聚合链接（合练、
   集成二进制、静态库打包）就是 `multiple definition`。
2. **不许把别包的源塞进 `sources`。** 那是把权责混在一起，且会让"谁拥有它"失去唯一答案。
3. **不许在聚合构建时直接拼接各包清单。** 必须**按去重后的源集合编译**（每源只编译一次）。

> **为什么单独立一节**：这个口子用包级验收**测不出来**。实测数据（一期当前状态）：
> `20/safepath.c` 与 `20/safepath_crc32c.c` 各被 3 个包引用，`30` 的四个源各被 2 个包引用——
> 引用合计 **22 处**，真实源只有 **14 个**。不去重就是 8 处重复编译。

### 14.3 机器强制（CI 每次都会跑）

`nxfs-impl` 的 `verify/check_deps.py` 已作为 `verify/run_all.py` 的**前置阶段**
（依赖图不通过就直接停，不再逐包构建）：

| 检查 | 内容 |
| :--- | :--- |
| 自检 | 每次运行先喂进 12 个已知坏/好形态（越界自有源、指向本包、指向不存在的包、拼错名、缺前缀、跨包同名、去重计数、头文件副本/遮蔽…），**必须恰好被抓到**——防"校验器悄悄失效于是全报 PASS" |
| A 源归属 | 每个自有源写在本包目录内；跨包同名源会被点名（重复实现的嫌疑） |
| B `link_only` 合法 | 必须指向真实存在的**别包**源；指向自己、指向不存在的包、拼错名字一律 FAIL |
| C 去重解析 | 输出聚合构建该用的权威去重源集合，并登记重复引用 |
| D 合并链接冒烟 | 把去重后的全部源链成**一个可执行文件**，证明无重复符号；并带**负对照**（不去重时多链一份副本对象，必须如期报重复符号）——否则如实报 FAIL，不假装通过；**要求了冒烟却缺 zig 时判 FAIL 而不是静默跳过**（"要求了却没做"正是本工具要防的失败模式） |
| E 头文件副本/遮蔽 | 包目录内出现 `nxfs.h` / `index.d.ts` 副本 → FAIL；跨包同名头**内容相同**（铁证是副本）→ FAIL；两包有依赖关系却同名不同内容（`-I` 顺序造成**静默遮蔽**）→ FAIL |
| F 规则重写 | 布局/格式**推导公式**在非所有者包里被重写（**含宏包装形式**）→ FAIL；**所有者的头文件里必须真的存在唯一实现点**，否则也 FAIL（"零重写"可能是"谁都没实现"）。详见 §14.4；登记表在 `verify/rule_registry.py` |

> **为什么 E 段单列**：重复的 `.c` 会被链接器抓到（D 段就是证明这件事），但**同名头文件的
> 遮蔽是静默的**——`-I` 顺序决定谁生效，谁都不报错。这类"重复依赖"只能靠机器查。

解析逻辑本身在共享库 `verify/nxfs_pkg.py`（`resolve_dependencies` → `DependencyGraph`），
与 `PackageSpec` 同源。**后续任何聚合构建（合练、集成二进制、静态库打包）都应当直接调用
`graph.dedup_sources`，不要自己拼清单**——这样"重复编译"在接口层面就不可能发生。

```powershell
python verify\check_deps.py                # 只看权属与去重（快，不需要编译器）
python verify\check_deps.py --link-smoke   # 追加合并链接冒烟 + 负对照
python verify\run_all.py                   # 正常入口：前置校验 + 逐包验收（默认含冒烟，--no-link-smoke 可跳）
```

> **实测坑（写工具时踩到的）**：`zig cc` 会把**完全相同的对象路径**传两遍当作输入去重而链过；
> 但**同内容、不同路径**的对象仍报 `duplicate symbol`。真实聚合场景里各包各建各的 `.o`
> （路径必然不同，甚至因 `-I`/宏不同而内容不同），所以负对照必须用**独立副本**，
> 否则冒烟形同虚设。

### 14.4 规则重复（第四类重复：重写公式）

前面 A/E 段管的是**文件**重复（源、头文件），本小节管**规则**重复——同一个推导公式在两个包里
各写一遍。它比文件重复更阴：**编译器、链接器、扫描都抓不到**，两侧漂移后谁都不报错。

#### 14.4.1 三条纪律

1. **一条布局/格式规则只有一个实现点**，且必须在规则的**所有者包**里
   （磁盘布局属包 20 的 `nxfs_disk_layout.h`；存储几何属包 30 的 `storage.h`；以此类推）。
2. **消费者只调用，不重写公式**——哪怕"一字不差"。注释里写"与包 X 一字不差"本身就是
   重写的自证；正确做法是让所有者把规则**导出**（头文件 `static inline` 或接口函数）。
3. **自描述值优先于现场推导**：盘上已写的地址（如总账里的 `secondary_lba`）就是权威；
   现场推导只用于**没有盘上数据可读**的场合（格式化）。见设计稿 §2.3。

> **优先级**：规则重复**不影响正确性时也应当消除**，但它的危害等级高于"代码难看"——
> 一旦漂移，消费者会拿着自己算出的地址去读写**另一个扇区**，而全链路无一处报错。
> 这是静默的数据面风险。

#### 14.4.2 登记表（一期当前状态）

机器强制在 `verify/rule_registry.py`（F 段）：**非所有者包里出现未登记的公式重写 → FAIL**
（**含宏包装形式**——第 3 处重写就是藏在一个宏里的，最初的模式没抓到）；
还会检查**所有者的头文件里真的存在唯一实现点**（"零重写"可能是"谁都没实现"）。
已登记的点每轮会打印出来（债务可见）；**已还清债务后请同步删掉登记行**。

| 规则 | 所有者 / 唯一实现点 | 现状（2026-09-26 对齐批次后） | 状态 |
| :--- | :--- | :--- | :--- |
| **R1** 副总账区起始 LBA＝容量中点向下对齐 1024 扇区 | `20-兼容层与安全路径/nxfs_disk_layout.h`：`nxfs_layout_secondary_ledger_lba()` + `nxfs_layout_secondary_ledger_usable()` | 20/30/40 **三处重写全部消除**：20 的两处调用点改调之；**30 的 `NXFS_STORAGE_SECONDARY_LBA` 宏改为别名**（原先又把公式写了一遍）；40 的 `led_secondary_lba()` 变为**无线公式的适配层** | ✅ **已消除**（零 ABI 成本） |
| **R2** 副引导表 LBA＝副总账 LBA＋总账区扇区数 | 同上：`nxfs_layout_boot_table_backup_lba()` | 20 的副引导表路径、40 的 `:825`/`:1050` 均改调之；**20 `:655` 那条"作用在副引导表地址上"的判据按 §4.3 影响面①原样保留**（不同址 ⇒ 不是同一条判据，替换即放宽） | ✅ **已消除** |
| 副总账/副引导表地址（**测试侧**独立复算） | —— | `40-元数据引擎/test/test_main.c`（R1 用字面量 `1023`、R2 用地址＋常量）与 `verify/fixtures/nxfs_fixture.h` 的 `NXFS_FX_SECONDARY_LBA` 字面量 | **永久允许**（这正是测试该做的事：抓常量漂移） |

### 14.5 副本地址上报（`§14.5` 对齐批次）——✅ **已落地**（API `v1.1.0` / ABI 1.2）

**提案（来自包 40）**：`nxfs_safe_ledger_result_t` 尾部追加"可信副本 LBA"，40 即可删掉
`led_secondary_lba()`。

**核实结论**（逐行看实现得出，与提案有三处差异——**都已按核实后的形态落地**）：

1. **字段名不对**：40 需要的是**副总账 LBA**（另一份副本的地址），不是"可信副本 LBA"。
   主副本地址是常量 `NXFS_LAYOUT_LEDGER_PRIMARY_LBA`，只有副的是推导值。
   ⇒ 落地为 `secondary_lba` **+ 两个引导表 LBA**（同属"上层需要的地址"，一次到位）。
2. **单靠结果字段不足以删掉函数**：`led_secondary_lba()` 的 5 个调用点里，**读副本**、**写副本**、
   **格式化**三处**没有 parse 结果可用**（格式化时总账还不存在）。⇒ 落地为：**函数保留为适配层**
   （探询容量 + 无立足区返回 0），有 parse 结果的路径优先消费上报值（40 `:664`）。
3. **盘上本来就自描述，只是被丢掉了**：`nxfs_disk_ledger_t::secondary_lba` 等三个字段从 v1 起
   就在盘上，是 20 解析时丢弃了它们。⇒ 落地为：**20 上报盘上自描述值** + 新增**自洽校验**。

**最终形态（两段都做了）**：

| 段 | 内容 | 结果 |
| :--- | :--- | :--- |
| **(a) 零 ABI 成本** | 推导规则单点化为 `nxfs_disk_layout.h` 的三个 `static inline`；20/30/40 三处重写全部改调之 | ✅ 三包验收数字**全未变**（228/781/396 全 0 失败）⇒ 行为零变化 |
| **(b) ABI MINOR** | `nxfs_safe_ledger_result_t` 尾部追加 `secondary_lba` / `boot_table_lba` / `boot_table_backup_lba`（`sizeof` 56 → **80**）；`NXFS_ABI_MINOR 1→2`、`NXFS_API_VERSION "1.0.1"→"1.1.0"`；**tag `v1.1.0`** | ✅ API 仓自检 **164 项**全过；实测 `size=80 align=8` |

**裁定（写进契约，实现方须遵守）**：三个值**取自盘上自描述字段**，不是现场推导；
**同一磁盘格式版本内，盘上值与推导规则不一致即判损坏**（布局演进必须走 `version`，不得静默漂移）。
落地分工：**不依赖容量**的自洽校验（对齐格点 / R2 关系 / 非零 / 主引导表=布局常量）放在 20 的解析里；
**"与容量推导一致"**那一半放在**合练 J7**（只有它同时握有夹具字面量、上报值与容量），
并已用定向变异证明该用例有牙（把夹具字面量改成"对齐但非中点"→ J7 精确报红）。

## 15. 实机安全红线（**死线**，2026-09-26 上级明令；优先级高于任何进度）

  以及 `B0` 自己的 QEMU+OVMF 固件验收；
- **"真实挂载"（`A0`/`80`）与"实机引导"必须由人在隔离环境**（独立虚拟机或**专用测试机**）执行；
  本仓只交付代码、镜像与操作说明，并在 `FREEZE.md` 记明"**真实挂载未验，留人工**"。
- **不确定某操作会不会碰实机时：不做，先报统筹。** 宁可少一个验收数字，不许赌一次真机。

## 16. 块大小与分区/卷管理的归属（2026-09-26 上级令补入）

> 上级原话：**「块大小这按实测来（分区时就有报告每块大小）」**；
> **「考虑把分区管理（包括但不限于创建移除格式化空间调整等任何文件系统都能做到的管理）职责补到某个包里，
> 如果不方便补到包里就独立实现」**；**「如果没法做驱动原生解决，即做不到在系统磁盘管理如同原生文件系统那样分区，
> 那就是需要工具的部分成功，不能完全认可」**。

### 16.1 块大小契约（**按实测，禁止假设**）

| 项 | 规定 |
| :--- | :--- |
| **设备/分区的块大小** | **一律按实测**：由**设备自述**（UEFI `BlockIo.Media.BlockSize` / 宿主平台的对应报告）给出，**分区时由分区管理面记录**。**任何地方都不许假设 512**。 |
| **FS 内部扇区单位** | 恒为 **512 B**（`NXFS_ST_SECTOR_BYTES`，冻结格式，**不改**）。设备块大小与它**不必相等**。 |
| **两者换算的唯一所有者** | **包 20**（`safepath_platform_*` 的 `sectors_per_block` 分支）。别包**不得**自己做这个换算，也不得假设"逻辑块 = 512"。 |
| **真机实测锚点** | OVMF 的 **VVFAT** 设备报 **`block_size=2048`**、`logical_partition=1`；NXFS 裸盘镜像报 **`block_size=512`**。两者**同机共存**（见 `vm_smoke` 串口实录）。 |
| **判据** | 真机取证必须**打印实际块大小**；任何"按 512 硬推"的代码路径都算缺陷。 |

### 16.2 归属裁定（按 `COORDINATION.md` §5.9 的六条判据逐条判过）

**结论：`20` 做不了（冻结面，且其权责是兼容/安全路径，不是磁盘管理）、`B0` 做不了（只读驱动）、
`A0` 是 OS 集成面（不宜同时当"隐身"与"可管理"的实现方）⇒ 按上级授权「不方便补到包里就独立实现」，
分区/卷管理**独立成包**：**

| 面 | 所有者 | 职责（**只此一份实现**，符合 §14「一个源只有一个所有者」） |
| :--- | :--- | :--- |
| **分区表读写 + 卷管理** | **新包 `D0-卷与分区管理`** | 分区表**读写**（MBR `0x7F` / GPT 自定义 GUID）、**创建 / 移除 / 空间调整**、**格式化入口**、**块大小的实测与记录**。**同一份实现**同时供**工具面**与**原生面**消费 —— 不为两条路各写一套。 |
| **原生（系统磁盘管理）** | **`A0-Windows集成层`** | 让系统**磁盘管理**能像原生文件系统那样**创建 / 移除 / 调整 / 格式化** NXFS 卷。**这是验收终点。** |
| **按偏移打开 + 块大小换算** | **包 20（最小扩展）** | 现在 `nxfs_sp_user_open` 从**偏移 0** 打开整文件 ⇒ 需支持"**按分区起始偏移打开**"，并按**设备自述块大小**换算。属**加性**扩展，不改既有冻结语义。 |
| **工具面** | `tools/`（`nxfs_image` 等） | 可先行提供 `--whole-disk`（写分区表 + 建分区 + 格式化），便于自测与取证。**但它只是中间阶段，不构成验收**。 |

### 16.3 与既有取向的张力（**已裁定：改"隐身"为"驱动认领"**）

现有设计**刻意**让 Windows/Linux**认不出** NXFS：MBR 类型字节取 `0x7F`、GPT 用随机 v4 GUID，
目的正是"**不自动挂载、不提示格式化**"（A0 开发包、README 硬性约束原如此写）。
而"**在系统磁盘管理里如同原生文件系统那样分区/格式化**"要求系统**认得出并管得了** NXFS。

**裁定（上级令 2026-09-26）**：既然独立实现，就**让驱动自己认领自家的文件系统并告诉操作系统**，
系统再**经驱动的分区管理模块**获得原生体验。⇒ 取向由"**隐身**"改为"**驱动认领 / 原生可管理**"。

| 项 | 结论 |
| :--- | :--- |
| **取向** | **驱动认领**（向 OS 注册 NXFS 的卷/文件系统身份）+ **原生可管理**；**不再以"系统认不出来"为目标**。A0 的职责行与 `AC-A0.8` 已按此改写。 |
| **标识数值** | **暂不改值**：MBR 类型字节 `0x7F` 经**自读权威表复核未被占用**（邻居 `0x71~0x74`、`0x76~0x7F` 空闲），本 FS 的 GPT GUID **未注册**且为合法 v4。改值属"将来若要正式注册"的事，须走 API 仓流程（`D0` 源码零改动，`AC-D0.16`）。 |
| **终极保险** | 批量改值工具 `.tools/nxfs_partid.py`（自读权威表：`--authority` / `--carriers` / `--self-test`）。**本地工具，不入库**。 |
| **`0x8E` 禁区** | **不变**：`0x8E`（Linux LVM）与 Microsoft 基本数据 GUID 仍**禁止**使用（会被误认）。 |

### 16.4 分期与验收口径

| 阶段 | 内容 | 是否构成验收 |
| :--- | :--- | :--- |
| **S1** | 工具面：分区表读写 + 建/删/调 + 格式化（镜像文件内，遵守 §15 实机红线） | ❌ **只算中间成功** |
| **S2** | 包 20 的"按偏移打开 + 按实测块大小"；`D0` 独立成包并接线 | ❌ 中间（但为 S3 前置） |
| **S3** | **原生**：系统磁盘管理里像原生文件系统一样创建/移除/调整/格式化（`A0`） | ✅ **验收终点** |

### 16.5 GUID 字节序契约（2026-09-26 补；由"驱动认领"要求逼出）

**背景**：上级令"让驱动自己认领自家的文件系统并告诉操作系统"。认领能否成立，**全看类型 GUID 在盘上
是否被写成 OS 期望的那 16 个字节** —— 写错一位，OS 端就不匹配，表现为"未格式化"或被误认，**且不报错**。

| 项 | 规定 |
| :--- | :--- |
| **内部/总账的 16 字节** | **显示序**（= GUID 字符串的书写顺序）。总账 `fs_type_guid[16]` 与夹具/工具的转换函数 `nxfs_fx_guid_to_bytes()` **都按显示序**，冻结格式**不变**。 |
| **GPT 条目里的 16 字节** | **混合端序**（UEFI 规范 `EFI_GUID`：前 3 个字段小端、后 2 个字段原序）。以本 FS 标识为例：<br>显示序 `13 07 3c 46 c0 da 46 96 81 7f 6d 12 90 25 15 e3`<br>盘上序 `46 3c 07 13 da c0 96 46 81 7f 6d 12 90 25 15 e3` |
| **转换的唯一所有者** | **`D0-卷与分区管理`**（`10-公共约定` §14「一个源只有一个所有者」）。别处**不得**再实现一份，也**不得**直接 `memcpy` 总账那 16 字节进 GPT 条目。 |
| **机器判据（必须有牙）** | ① 正反两向转换的**往返一致**；② 用**独立实现**（不引用 D0）从生成的 GPT 字节里读出类型 GUID，必须与单一事实源**逐字节相同**；③ **负对照**：故意按显示序直写 ⇒ 独立实现读出的 GUID **必须与事实源不同**（该用例必须能红）。 |
| **MBR 侧** | 无字节序问题（单字节）；但仍须：类型字节取自 `NXFS_MBR_TYPE_BYTE`（单一事实源），不得写字面量。 |
