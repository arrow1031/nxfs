# 10 · 公共约定（全局必读）

> 本文件是**唯一全局必读**文档。所有块开发包引用此处定义，**不重复定义**。
> 修改全局约束只改本文件——这是控制 Token 膨胀的关键规则。

---

## 1. 术语与命名

**两组"层"含义不同，严禁混称**（混称会同时导致深度上限设错与层间对应表出错）：

| 称谓 | 含义 | 取值 |
| :--- | :--- | :--- |
| **契约层** | API 调用契约分层 | L0 介质 / L1 原语 / L2 契约 / L3 数据面 / L4 安全路径 |
| **数据层** | 日志区的数据分层 | 顶层（根层） / 中间层 / 底层 |

**"深度"一律指契约层的调用/结构深度**，上限 16；数据层固定 3 层，与深度无关。

**责任主体（Subject）**：缓存一致性的最小权威粒度。任何缓存条目的有效性只由
`(kind, a, b) + 世代号` 决定，**不由卷级或全局事务号决定**。见 §6。

## 2. 单位与编码（全部强制）

| 对象 | 约定 |
| :--- | :--- |
| 路径 | UTF-8 字节串 + **显式长度**，**非** NUL 终止 |
| 文件名编码 | 必须支持 **WTF-8**（含未配对代理对），以完整兼容 NTFS 文件名 |
| 时间 | 纳秒，`int64`，Unix epoch |
| 容量 | 字节，`uint64` |
| 偏移 | **簇号**，`uint32`；区间为半开 `[start, start + count)` |
| 比例 | **万分比整数** 0–10000（禁止浮点——跨平台舍入差异会让阈值不可复现） |
| LBA | 扇区为单位（仅安全路径与坏道报告使用），`uint64` |

## 3. 规范常量（编译期可核对，禁止硬编码副本）

```c
#define NXFS_SAFEPATH_IO_TIMEOUT_MS 100u   /* 硬性，超时即错误返回 */
#define NXFS_SAFEPATH_MAX_DEPTH     16u    /* 调用/结构深度 */
#define NXFS_SAFEPATH_EVENT_SIZE    64u    /* 定长事件记录 */
#define NXFS_RING_SLOT_SIZE         4096u  /* 整页 */
#define NXFS_RING_SLOT_HEADER_SIZE  128u
#define NXFS_RING_PAYLOAD_MAX       3968u  /* 4096 - 128 */
#define NXFS_PATH_MAX_BYTES         32768u
#define NXFS_NAME_MAX_BYTES         255u
```

### 磁盘格式常量

| 项 | 值 |
| :--- | :--- |
| 簇大小 | 4096 B（可配置 16384 / 65536） |
| 每簇头部 | CRC32C 校验和（CPU 计算，存储层只搬簇，不解释） |
| 索引条目宽度 | **8 B** = 4B 簇号 + 2B 长度 + 1B 状态 + 1B 校验 |
| 兼容区 | 32–64 MB，仅承担传统 BIOS 引导与引导配置 |
| 主总账 | 64–256 KB，分区头 |
| 副总账 | 分区中部，结构与主总账相同 |
| 跨文件区 | 256 MB–1 GB |
| 引导文件表 | 固定 **4** 个条目 |

### 分区标识（**不要改，尤其不要用 0x8E**）

| 项 | 值 | 理由 |
| :--- | :--- | :--- |
| MBR 类型字节 | **`0x7F`** | `0x8E` 是 **Linux LVM**，会让 Linux 侧探测逻辑误认并触发自动激活 |
| GPT 类型 GUID | **`13073c46-c0da-4696-817f-6d12902515e3`** | 随机 v4；不能用 Microsoft 基本数据 GUID（会被 Windows 提示格式化） |

取证依据：util-linux 2.42.3 `include/pt-mbr-partnames.h` / `pt-gpt-partnames.h`。

### 策略参数

| 项 | 值 |
| :--- | :--- |
| 检查点间隔 | 30–60 min；日志总量超分区容量 **1%** 时强制 |
| 紧急空闲空间 | **5%**，冷数据/常规写入不得占用 |
| 预留回收触发 | 预留浪费率 > **30%** |
| 古旧文件定义 | > 6 个月未修改 **且** 预留使用率 < 20% |
| 日志区隔离带 | 子文件夹日志区之间 **≥ 1 簇** |
| 块内间隔 | 1–2 簇缓冲带 |
| 程序文件大文件阈值 | **> 64 MB 独立成块** |
| 日志量基线（1000 文件夹） | 顶层 ~64 KB / 中间 ~3.2 MB / 底层 ~115 MB |

## 4. 错误码使用纪律

错误码全表见 `nxfs.h`（负值域）。此处只规定**必须遵守的三条纪律**：

### 纪律一：三种"失败"必须区分，绝不合并

| 结果类别 | 正确处置 | 用码 |
| :--- | :--- | :--- |
| 数据未写入 | **可重试** | `NXFS_ERR_TIMEOUT` 等通用码 |
| 数据可能写了一半 | 靠 CRC32C 识别并丢弃 | `NXFS_ERR_CORRUPT` |
| **数据已写入、完整性不确定** | **不可重试**（重试会制造第二次不确定），必须靠 CRC32C 事后核验 + 降级链 | `NXFS_ERR_INTEGRITY_UNCERTAIN` / `NXFS_ERR_SAFEPATH_APPEND_UNCERTAIN` |

第三类是"主总账校验和不过 → 走副总账"这条恢复路径的**具体成因**，因此必须独立成码。

### 纪律二：快速重试必须声明，不得沉默

安全路径 `sector_write` 失败后允许**一次最快最小重试**，但：

- 返回 `NXFS_ERR_SAFEPATH_QUICK_RETRY_DONE` 并置 `quick_retry_done = 1` —— **明确告知调用方本次结果不是终局**；
- 最小重试 = 剥除一切可选环节（无分配、无日志、无状态机），只做那一次必要的扇区写；
- **不得成为可关闭选项**（允许关闭就等于让"重试策略"进入安全路径，违反分层原则）。

### 纪律三：降级必须可见

能力位请求后若不支持，必须回报被忽略的位（`features_ignored`）。静默降级不允许。

## 5. 分层不变量（违反即为设计错误）

| ID | 不变量 |
| :--- | :--- |
| `INV-1` | **安全路径（L4）不做策略**：只暴露扇区读写、CRC32C、总账解析、引导表解析、内核读取、事件追加。需要策略或分配的操作一律返回 `NXFS_ERR_SAFEPATH_FORBIDDEN` |
| `INV-2` | **安全路径零动态分配**：所有缓冲区由调用方提供，不链接分配器 |
| `INV-3` | **安全路径状态在调用方**。唯一例外是 `event_append`，且必须在头文件中显式标注为例外 |
| `INV-4` | **存储抽象层只搬簇，不解释簇内容**。CRC32C 由 CPU 计算，存储层不解析元数据 |
| `INV-5` | **L4 与 L2 边界分离但语义对应**：L4 写入的数据 L2 必须能正确读取，反之亦然 |
| `INV-6` | **可引导卷上，引导文件表所指文件豁免物理迁移**（卷级不变量，非调用方可选项）。理由：否则冷启动阶段一按总账 LBA 直读会读到已蒸发或复用的块 |
| `INV-7` | **实现能力 ≠ 卷属性**：`NXFS_CAP_BOOT`（此实现具备引导能力）与 `NXFS_VOLATTR_BOOTABLE`（此卷可引导，挂载时探测）不可混用 |
| `INV-8` | **紧急保留空间不被常规写入占用**，仅用于避免"缺口不可见" |
| `INV-9` | **禁止在 UTF-8 校验阶段拒绝合法卷内名称**（必须支持 WTF-8） |
| `INV-10` | **索引条目按簇对齐** |

## 6. 责任主体与缓存一致性（跨多块，故置于公共约定）

### 六类主体划分

| 被缓存的事实 | kind | `a` | `b` |
| :--- | :--- | :--- | :--- |
| 文件元数据 / inode / 簇映射 | `FILE` | FileId | 0 |
| 目录列表 / 子文件夹偏移 | `FOLDER_LOG` | FolderId | 0 |
| 类型标记（普通/程序） | `PARENT_LOG_ENTRY` | FolderId | 条目下标 |
| 块空闲池、extent 归属、预留量 | `EXTENT` | 起始簇 | 簇数 |
| 坏的 / 待处理扇区 | `BAD_SECTOR_SHARD` | 分片号 | 0 |
| 跨文件区条目 | `CROSSFILE_ENTRY` | 条目序号 | 0 |

辅助：`DEFERRED_EVENT`（延后事件）、`VOLUME`（仅限挂载/卸载等**整卷结构变更**，**不可**用于常规变更）。

**不设主体**：空间水位、紧急保留量 —— 必须全局精确，不可缓存。

### 世代号规则

- 世代号**只在权威性变更时递增**，0 为非法值。
- 校验是**版本比较**，不是匹配清单。因此失效通知**幂等、可丢失、可乱序、可重放**：
  漏收一条不会造成永久陈旧，收到重复也无副作用。
- **变更类操作必须回传受影响主体集合**（`affected`）。缺少它，调用方只能保守地大面积
  丢弃缓存，"最小责任主体"就白设计了。

### 主体冻结（升降层专用）

| 状态 | 语义 |
| :--- | :--- |
| `ACTIVE` | 可读写，缓存可直接信任 |
| `FROZEN` | **拒绝新写入**（返回 `NXFS_ERR_SUBJECT_FROZEN`），缓存按映射转换或丢弃 |
| `CONVERTING` | 预算内增量转换，**可中断续作** |
| `DEAD` | 必须整体丢弃 |

**冻结后不得静默接受新写入**——否则会出现两个都"看起来有效"的主体，这是最坏情况。

### 移交裁定（两条容易搞错）

| 规则 | 说明 |
| :--- | :--- |
| 资格与执行解耦 | 进度越过半数是**资格**，窗口边界才是**执行时机**；世代号在**移交完成时**递增，**不在越线时**递增 |
| 空窗口完全无操作 | 不递增任何世代、不产生任何失效。否则每个窗口边界都造成无意义的缓存失效风暴 |
| 权威不对称 | 目标侧"已确认接收"是**完整证明**；源侧记录只是**辅证**，能补强、**不能否证** |

## 7. 提交与可见性（数据面）

```c
typedef enum nxfs_slot_state {
    NXFS_SLOT_FREE = 0x00, NXFS_SLOT_WRITING = 0x01,
    NXFS_SLOT_COMMITTED = 0x02, NXFS_SLOT_ACKED = 0x03,
    NXFS_SLOT_ABORTED = 0xFE
} nxfs_slot_state_t;
```

**三条硬规则**：

1. **只有 `COMMITTED` 的槽位可见**；之前的内容一律不可读——这不是优化，是防止读到撕裂的元数据。
2. 生产者以 **release** 语义发布 `COMMITTED`，消费者以 **acquire** 语义读取。
3. `acked_seq` **可跳跃**（是"已确认的最高序号"，不是连续确认数）——批量提交允许乱序完成。

**缓存只缓存已提交事务的元数据**（设计稿 §6.4）。卷的 `mounted_at_seq` 是全局基准点，
用于判断"整体视图是否过时到需要重整"，**不用于逐个条目校验**（那是世代号的职责）。

## 8. 兼容性机制（跨块强制）

| 机制 | 做法 |
| :--- | :--- |
| 结构体版本化 | 首字段 `struct_size`；只允许**尾部追加**字段，禁止改序 / 改宽 / 复用保留字段 |
| 函数指针表 | 只导出 2 个符号；v1/v2 可在同进程共存 |
| 能力位 | 位域；**未知位必须被忽略** |
| 8 字节对齐 | 跨 ABI 边界结构体一律 `NXFS_ALIGN8` |
| 命名 | 全部符号加 `nxfs_` / `NXFS_` 前缀 |
| 保留名 | 必须拦截 Windows 设备名（`CON`/`PRN`/`AUX`/`NUL`/`COM1-9`/`LPT1-9`，含带扩展名形式）与 NTFS 元数据名（`$MFT`/`$LogFile`/`$Bitmap`/`$Boot`/`$UpCase`/`$Extend`） |

> 为什么强制 8 字节对齐：同一结构体在 System V AMD64 与 MSVC/Windows x64 下
> `_Alignof` 可能不同（例如成员最大仅 4 字节时前者给 4、后者给 8），导致共享内存
> 结构体数组**静默错位**。NXFS 编写期已实际踩过（`nxfs_safe_io_result_t`）。

## 9. 编码规范

| 项 | 约定 |
| :--- | :--- |
| 语言 | C11 为基线；头文件必须同时能被 C++17 编译 |
| 警告 | `-Wall -Wextra -Werror` 零容忍 |
| 动态分配 | 安全路径**禁止**；其余模块允许但必须在包内声明分配点 |
| 断言 | 安全路径禁止 `assert`；其他模块可用但不得用于用户可控输入 |
| 错误处理 | 所有函数返回状态码；`out` 参数仅在返回 `NXFS_OK` 时有效 |
| 长度校验 | 任何来自外部的长度/偏移都必须先校验再使用 |

## 11. 总开发期与环节

> **命名规则**：**期**（一期 / 二期）是最高层；**环节**是子开发级别；
> **阶段**另有用途，不表示开发进度（见下）。

| 期 | 内容 | 状态 |
| :--- | :--- | :--- |
| **一期** | **机械盘侧全部开发**（`20`～`B0` 共 10 个包） | 🚧 当前进行中 |
| **二期** | **NAND 相关全部功能**（设计稿 §十五 + 包 `C0`） | ⏸️ 已冻结，待一期可用后开启 |

| 环节 | 内容 |
| :--- | :--- |
| **一期 · 环节1** | 只读最小可跑：`20` → `30` → `40`(只读) |
| **一期 · 环节2** | 写入路径：`40`(CoW) → `50` → `70` → `60` |
| **一期 · 环节3** | 集成与优化：`80` → `A0` → `90` → `B0` |
| **二期 · 环节1** | NAND 缓存（冻结） |

> ⚠️ **"阶段"不表示开发进度**，它在本文档中专指另外两件事：
> `B0` 的**三阶段引导流程**（UEFI 固件 → 内核初始化 → 高级驱动）、
> 以及 `60` 的**四个动作步状态机**（待分发 → 分发中 → 转移完成 → 回收）。
> 不要用"阶段"表示子开发。

**NAND 冻结范围（一个都不做）**：设计稿 §十五、模块表中的"NAND 缓存层"与存储抽象层
的"NAND 缓存管理"职责、API 中三个 NAND 能力位（`NXFS_CAP_NAND_CACHE` /
`NXFS_VOLATTR_HAS_NAND_CACHE` / `NXFS_FEATURE_NAND_CACHE`）、开发包 `C0`。
