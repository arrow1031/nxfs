## 关键设计点

### 1. 簇头部与校验和的分工

```
簇 = [CRC32C 头部][簇数据]
        ↑ CPU 计算，存储层只搬
```

- **存储层不解释簇数据**，只负责：搬簇、算/验头部校验和。
- 校验失败必须区分**读失败**与**校验失败**：
  - 读失败（设备报错）→ `NXFS_ERR_TIMEOUT` / `NXFS_ERR_CORRUPT`
  - 校验失败（读到了但内容不符）→ `NXFS_ERR_CORRUPT`，且**必须上报具体簇号**给上层做修复决策
- `NXFS_VERIFY_NONE / CRC32C / CRC32C_AND_REPAIR` 三档由**调用方**选择，本层不替它决定。

### 2. 坏道位图是**分区级**、分片的

设计稿 §11.2 要求"元数据引擎维护坏道位图，分配器跳过这些区域"。落到实现：

- 位图按**分片**管理，每片是一个 `BAD_SECTOR_SHARD` 责任主体（`a` = 分片号）。
  分片的意义：一片变更只失效一片缓存，不会让整张位图的缓存全废。
- 位图本身必须**带校验和且可重建**（它是派生的，不是权威数据）。损坏时从扫描重建，
  而不是让挂载失败。
- 分配器只**读**位图；**写**位图由本层的坏道上报路径完成。

### 3. 写入触发修复（两个不同场景，不要混）

| 场景 | 触发条件 | 动作 |
| :--- | :--- | :--- |
| 读错误触发修复 | 读某簇失败 | 主动发起一次**写**到同一位置，触发固件重映射，然后重读 |
| 写入即修复 | 目标是标记为"待处理"的扇区 | 直接写入即触发重映射 |

**重要**：读错误触发修复是**写操作**，因而可能遇到 `INTEGRITY_UNCERTAIN`。
必须把它当写操作处理（走两段式失败模型），不能当读操作。

### 4. S.M.A.R.T. 阈值与"恶化"判定

- 采集 `reallocated_sectors` / `pending_sectors` / `uncorrectable_sectors`。
- **调用方不应硬编码索引语义**（不同盘的属性 ID 不同）——本层负责把厂商属性映射为
  统一语义，上层只读归一化字段。
- 恶化超阈值 → 触发数据迁移，并**登记事件**（不是静默干活）：
  `NXFS_EVENT_BAD_SECTOR_MIGRATION_PENDING = 10`（低优先，因为它不威胁完整性）。

### 5. 紧急保留空间的边界

`INV-8`：**紧急保留空间不被常规写入占用**。本层必须在分配前检查：

```
需要空间 → 可用量 - 紧急保留(5%) 是否够？
   ├─ 够 → 正常分配
   └─ 不够 → 返回 NXFS_ERR_NO_SPACE
              （只有"避免缺口不可见"这类用途才可借用，见 20 包的事件区）
```

### 6. 批量提交（与 L3 对接）

- 热路径不逐操作 IPC —— 本层需提供**批量簇读写**入口，由数据面 ring 驱动。
- 提交顺序：同一批次内**顺序落盘**，避免机械盘寻道抖动。
- 返回 `commit_seq` 供上层做缓存基准点。

## 验收标准

| ID | 标准 | 验证方式 |
| :--- | :--- | :--- |
| `AC-30.1` | 簇读写往返一致，含跨界（非 4KB 对齐）读写 | 随机偏移往返测试 |
| `AC-30.2` | CRC32C 校验失败时返回 `CORRUPT` 且**上报具体簇号** | 篡改单簇头部 |
| `AC-30.3` | 读错误触发一次写修复；该写失败时返回写类错误（非读类） | 注入读失败 |
| `AC-30.4` | 坏道位图损坏时可从扫描重建，且**不导致挂载失败** | 清空位图区 |
| `AC-30.5` | 位图分片变更只影响该分片的世代号 | 断言其他分片 gen 不变 |
| `AC-30.6` | 常规写入**不占用**紧急保留空间 | 填至 95% 后写入应返回 `NO_SPACE` |
| `AC-30.7` | S.M.A.R.T. 属性映射为统一语义；`smart_available == 0` 时不报错 | 无 SMART 的虚拟设备 |
| `AC-30.8` | 批量簇读写按顺序落盘（可用 trace 验证顺序） | 记录 LBA 序列 |
| `AC-30.9` | **NAND 能力探测恒返回"不可用"**，且不产生 NAND 相关调用 | 桩测试 |
| `AC-30.10` | 只读设备上任何写路径返回 `NXFS_ERR_READ_ONLY` 或 `DEVICE_WRITE_PROTECTED` | 只读挂载 |

## 常见坑

1. **不要把"读失败"与"校验失败"混成一个码**——它们的修复动作不同（前者重映射，后者重建）。
2. **CRC32C 的多项式别用错**（Castagnoli）。见 `20` 包坑 5。
3. **坏道位图不是权威数据**。它损坏时重建，不要让整个卷挂载失败。
4. **紧急保留的检查必须在分配之前**，不是写入失败之后再回滚。
5. `nxfs_device_health_t` 的字段是**归一化**的；不要把厂商原始属性 ID 暴露给上层。
6. 批量提交的 `acked_seq` **可跳跃**，不要假设连续。
