## 1. 边界与权责

### 1.1 一句话定位

`D0` 是**唯一一份**分区/卷管理实现：**分区表读写** + **卷管理动作**（创建/移除/空间调整）+ **格式化入口**
+ **块大小的实测与记录**。**同一份实现同时供工具面与原生面消费**，不为两条路各写一套
（符合 `10-公共约定.md` §14「一个源只有一个所有者」）。

### 1.2 `D0` 拥有（唯一实现点）

| 面 | 内容 |
| :--- | :--- |
| **分区表读写** | MBR 分区表的**解析与生成**；GPT 分区表的**解析与生成**（主表 + 备份表 + 表头 CRC32 + 条目数组 CRC32）。 |
| **GUID 字节序转换** | 显示序 ↔ GPT 条目混合端序（UEFI `EFI_GUID`）的**唯一实现点**（`10-公共约定.md` §16.5）。 |
| **卷管理动作** | **创建 / 移除 / 空间调整**。调整含"扩"与"缩"，缩须先满足文件系统侧条件（见 §5.3）。 |
| **格式化入口** | 调用方给出几何（簇大小、容量、分区类型标识）→ 产出可挂载的 NXFS 卷；**不自己发明盘上布局**。 |
| **块大小的实测与记录** | 从**设备自述**取块大小（UEFI `BlockIo.Media.BlockSize` / 宿主平台对应报告），**在分区时记录**；把"分区起始偏移 + 设备块大小"交给包 `20`。 |
| **对齐判定** | 分区起始偏移与设备块大小、簇大小的一致性判定（不满足 ⇒ 明确报错，见 `AC-D0.14`）。 |

### 1.3 `D0` 不拥有（严禁越界）

| 不拥有项 | 所有者 | 依据 |
| :--- | :--- | :--- |
| **NXFS 盘上布局常量**（总账 LBA、副引导表 LBA、簇大小换算等） | `20`/`30`/`40`/`50` 各自的格式头 | `10-公共约定.md` §16.2；§14.4.1「一条布局/格式规则只有一个实现点」 |
| **设备块大小换算**（"设备块 ↔ 512B 扇区"的换算） | **包 `20`**（`safepath_platform_*` 的 `sectors_per_block` 分支） | `10-公共约定.md` §16.1、§16.2 |
| **OS 侧可见性 / 集成**（系统磁盘管理里的呈现、驱动认领） | **`A0-Windows集成层`** | `10-公共约定.md` §16.2 |
| **设备 IO 本身**（读/写物理设备或镜像文件的底层调用） | 工具面调用方 / `20` 的平台层 | 本包只做**纯逻辑层**（§1.4 边界） |
| **NAND 缓存相关** | 二期冻结 | `10-公共约定.md` §11 |
| **宿主物理盘/真实卷的任何读写** | 任何包都不许 | `10-公共约定.md` §15（死线） |

### 1.4 纯逻辑层边界（第一批次的形态约束）

第一批次（S1 最小切片）**只做"读 + 写"分区表这一件事**，形态为**纯逻辑层**：

- **入参**：盘的总扇区数（`uint64`）、设备块大小（`uint32`，字节）、要建/删/调的分区描述数组；
- **出参**：分区表字节 + 校验结果；
- **不做**：不打开设备、不调用任何 IO、不做几何换算、不做块大小到扇区的换算；
- **不做**：不分配内存（`10-公共约定.md` §9 安全路径禁止动态分配；`D0` 虽非安全路径，
  但纯逻辑层一律由**调用方提供缓冲区**，便于工具面与原生面共用同一实现）。

> 这条边界使 `D0` 可以在**内存夹具**里被完整验收（§15 允许的写入面②），
> 不需要任何真实设备参与，也不需要 QEMU。

### 1.5 与既有取向的张力（**待裁定项，不得自行落地**）

现有设计**刻意**让 Windows/Linux **认不出** NXFS（MBR 类型字节 `0x7F`、GPT 随机 v4 GUID），
目的是"不自动挂载、不提示格式化"。而 S3 要求系统**认得出并管得了** NXFS。

⇒ 二者方向相反。按上级令"验收终点是原生"，`0x7F` / 随机 GUID 的**取向须修正**为
「被正确识别为 NXFS、且不被误当成 LVM（`0x8E`）/未格式化」。

**该修正触动冻结约定（README 硬性约束表 + `10-公共约定.md`），须上级明确点头后落地。**

**在点头之前，本包只做两件事**：

1. **登记事实**（本节），不改任何常量值；
2. **把分区类型标识设计成入参**（`AC-D0.16`）：MBR 类型字节与 GPT 类型 GUID 由调用方传入，
   其**权威值归 `10-公共约定` 所有者**，`D0` 不得内嵌字面量。取向裁定后**只改一处**。

## 3. 术语与单位（本包内约定，均来自 `10-公共约定.md` §2）

| 对象 | 约定 |
| :--- | :--- |
| 扇区 | **恒为 512 B**（`NXFS_ST_SECTOR_BYTES`，冻结格式）；设备块大小**不必**等于它 |
| 设备块大小 | 字节，`uint32`；**按实测**（设备自述），**任何地方都不许假设 512** |
| 偏移 | 分区表内一律**LBA（扇区为单位，`uint64`）**；`D0` 只搬运与判定，不做换算 |
| 容量 | 字节，`uint64`；LBA 到字节的换算由调用方或 `20` 完成 |
| 校验 | CRC32C（GPT 表头 / 条目数组）；**算法归 `20` 的 `safepath_crc32c`**，`D0` 经头文件调用，**不自写** |
| 比例 | 万分比整数 0–10000（禁浮点） |
| 时间 | 纳秒，`int64`，Unix epoch |

### 3.1 盘上结构尺寸（GPT，来自 UEFI 规范，非本包发明）

| 项 | 值 |
| :--- | :--- |
| GPT 表头 | 92 字节（`sizeof` 锁定，编译期断言） |
| GPT 条目 | **128 字节**/条 |
| GPT 条目数组最小 | 16 KiB（128 条 × 128 字节） |
| GPT 主表 LBA | 1（`LBA 0` 为保护性 MBR） |
| GPT 备份表位置 | 盘尾：备份条目数组 + 备份表头（末 LBA） |
| GPT 表头签名 | `"EFI PART"`（8 字节，`0x5452415020494645` 小端） |
| 保护性 MBR 类型 | `0xEE`（UEFI 规范固定，**不是** NXFS 类型标识） |

> 以上数值属 UEFI 规范公共知识，**不是** NXFS 布局常量，故不受 §14.4 的"唯一实现点"约束；
> 但仍须**编译期断言**锁定 `sizeof`，禁止手写魔数散落各处（`10-公共约定.md` §9 + 本仓硬纪律 8）。

## 4. 验收标准清单

> 格式：**ID · 标准 · 验证方式 · 负对照/边界**。
> 每条 AC 至少一个用例；"一个不会失败的自检等于没有自检"（本仓纪律 7）。
> 验证方式里的**打印标记**为固定字符串，供 `build.py` 正则提取（形如 `[D0-AC-D0.1] PASS`）。
> 负对照用例的标记为 `[D0-AC-D0.1-NEG] PASS`（负对照**预期失败**，故 PASS 表示"如期报错"）。

### 4.1 GUID 字节序（★ 最高优先，`10-公共约定.md` §16.5）

#### AC-D0.1 · GUID 显示序 ↔ 盘上序 往返一致

- **标准**：对任意 16 字节 GUID，`to_disk(from_disk(b)) == b` 且 `from_disk(to_disk(b)) == b`（双向恒等）。
- **验证方式**：`test/test_guid.c`，对**规范给的样例**与**≥ 32 组确定性伪随机样本**跑双向转换；
  打印 `[D0-AC-D0.1] PASS roundtrip=<N>`（N 为样本数）。
- **负对照/边界**：零 GUID（全 `0x00`）、全 `0xFF`、以及**前 3 字段首字节互不相等**的样本
  （若实现漏了某个字段的端序翻转，这类样本必红）；打印 `[D0-AC-D0.1-NEG] PASS`。

#### AC-D0.2 · 本 FS 标识的盘上序逐字节正确

- **标准**：显示序 `13 07 3c 46 c0 da 46 96 81 7f 6d 12 90 25 15 e3`
  → 盘上序 `46 3c 07 13 da c0 96 46 81 7f 6d 12 90 25 15 e3`，**逐字节相同**。
- **验证方式**：`test/test_guid.c` 内**字面量对照**（测试侧独立复算，属 §14.4 表内"永久允许"的测试侧复算）；
  打印 `[D0-AC-D0.2] PASS`。
- **负对照/边界**：断言**首 4 字节**与显示序首 4 字节**不同**（若实现"原样直传"，此处必红）；
  打印 `[D0-AC-D0.2-NEG] PASS`。

#### AC-D0.3 · 独立实现从生成的 GPT 字节里读出类型 GUID，与单一事实源逐字节相同

- **标准**：`D0` 生成一个含本 FS 类型 GUID 的 GPT 条目；一个**不引用 `D0` 任何符号**的独立读取器
  （仅按 UEFI 规范解析字节）读出的 16 字节 == 单一事实源给出的显示序经规范转换后的盘上序。
- **验证方式**：`test/test_guid_independent.c`（独立读取器为**本测试文件内的静态函数**，
  **不 include `d0_guid.h`**，只用 `<stdint.h>` 与手写偏移）；
  打印 `[D0-AC-D0.3] PASS guid=<hex32>`。
- **负对照/边界**：独立读取器**读到的字节序列**与"显示序直写"的字节序列**必须不同**；
  打印 `[D0-AC-D0.3-NEG] PASS`。

#### AC-D0.4 · 负对照：故意按显示序直写 ⇒ 独立实现读出的 GUID 必须不同

- **标准**：把 GPT 条目的类型 GUID 字段**故意填成显示序 16 字节**（错误做法），
  独立读取器读出的 GUID **必须与单一事实源不同**。
- **验证方式**：`test/test_guid_independent.c` 的变异用例；
  打印 `[D0-AC-D0.4] PASS mismatch=1`。
- **负对照/边界**：若此处**未报差异**，说明独立读取器与事实源同源（自说自话），判 FAIL。
  **该用例必须能红**（把 `d0_guid.c` 的转换函数改为恒等映射，`AC-D0.4` 必须 FAIL）。
- **反向变异验证**：`build.py` 提供一个 `--mutate-guid-identity` 开关（仅测试构建），
  把转换改为恒等后重跑，**要求 `AC-D0.4` 报红**；报红即 `[D0-AC-D0.4-MUT] PASS`。

#### AC-D0.5 · 转换的唯一实现点

- **标准**：全仓扫描（`D0` 目录 + 别包目录）中，GUID 端序转换逻辑只出现在 `d0_guid.c` 一处；
  别处出现该模式的宏包装形式也算违规。
- **验证方式**：`build.py` 内的源码模式扫描（与 `verify/rule_registry.py` F 段同风格），
  扫描目标：`D0-卷与分区管理/` 全部源 + 已冻结别包目录；
  打印 `[D0-AC-D0.5] PASS hits=1`。
- **负对照/边界**：扫描器先喂入一个**已知含第二处实现**的合成样本，**必须被抓到**；
  打印 `[D0-AC-D0.5-NEG] PASS`。

### 4.2 分区表解析（MBR / GPT 双向）

#### AC-D0.6 · MBR 解析：合法表往返一致

- **标准**：给定一个合法的 MBR 字节块（512 字节），`D0` 解析出的分区描述集合，
  再经 `D0` 生成回字节，**逐字节相同**（往返一致）。
- **验证方式**：`test/test_mbr.c`，至少 3 组夹具：1 个分区 / 4 个分区（上限）/ 混合类型；
  打印 `[D0-AC-D0.6] PASS cases=<N>`。
- **负对照/边界**：**4 个主分区上限**（见 `AC-D0.11`）；空分区表（全零条目）必须解析为"0 个分区"而非报错；
  打印 `[D0-AC-D0.6-NEG] PASS`。

#### AC-D0.7 · MBR 解析：签名错 / 截断必须明确报错，不猜

- **标准**：MBR 签名（`0x55AA` @ offset 510）缺失或错误 ⇒ 返回**明确的**解析失败码；
  输入长度 < 512 ⇒ 返回明确的长度不足码。**不得**返回"0 个分区"。
- **验证方式**：`test/test_mbr.c`；打印 `[D0-AC-D0.7] PASS rc=<code>`。
- **负对照/边界**：三种畸形各一例 —— ① 签名错（`0x55AA` → `0x0000`）；
  ② 长度 511 字节；③ 签名正确但**条目内起始 LBA + 扇区数溢出 `uint64`**；
  打印 `[D0-AC-D0.7-NEG] PASS cases=3`。

#### AC-D0.8 · GPT 解析：合法表往返一致（含主/备表）

- **标准**：合法 GPT 字节块 → 解析出描述 → 生成回字节 → 逐字节相同；
  **主表与备份表内容必须互为镜像**（条目数组与表头字段一致，仅 `MyLBA` / `AlternateLBA` 互换）。
- **验证方式**：`test/test_gpt.c`，夹具含 1 条目 / 128 条目（上限）/ 盘尾备份表；
  打印 `[D0-AC-D0.8] PASS cases=<N>`。
- **负对照/边界**：备份表缺失 ⇒ 明确报错（不是静默用主表）；
  打印 `[D0-AC-D0.8-NEG] PASS`。

#### AC-D0.9 · GPT 解析：CRC32C 不符 / 签名错 / 截断必须明确报错

- **标准**：表头 CRC32 不符、条目数组 CRC32 不符、签名非 `"EFI PART"`、长度不足
  ⇒ 各自返回**可区分**的明确错误码。**不得**回退到"用主表凑合"。
- **验证方式**：`test/test_gpt.c`；打印 `[D0-AC-D0.9] PASS cases=4`。
- **负对照/边界**：四种畸形各一例，且**逐一变异单字节**证明每类都被抓；
  打印 `[D0-AC-D0.9-NEG] PASS cases=4`。

#### AC-D0.10 · GPT 备份表不一致 ⇒ 明确报错，不静默选边

- **标准**：主表与备份表**任一**关键字段（`HeaderCRC32`、`PartitionEntryLBA`、
  `NumberOfPartitionEntries`、`FirstUsableLBA`、`LastUsableLBA`、条目数组内容）不一致
  ⇒ 返回明确的"备份表不一致"错误码。
- **验证方式**：`test/test_gpt.c`；打印 `[D0-AC-D0.10] PASS fields=6`。
- **负对照/边界**：六个字段各造一例不一致；**外加**"主表损坏 + 备份表完好"与
  "备份表损坏 + 主表完好"两例（前者**必须报错**，后者**必须报错**——`D0` 是管理面，
  不像 L4 恢复路径那样允许降级；见 `AC-D0.10` 的裁定说明）；
  打印 `[D0-AC-D0.10-NEG] PASS cases=8`。

> **裁定说明**：包 `20` 的 L4 安全路径在"主总账校验和不过 → 走副总账"时允许降级，
> 那是**恢复路径**。`D0` 是**管理面**，任何不一致都意味着盘上状态可疑，
> 静默选边会让"两个都看起来有效"，这是最坏情况（`10-公共约定.md` §6 主体冻结同款理由）。
> 因此 `D0` **一律报错**，由调用方决定是否用某一侧强制重建。

### 4.3 分区表生成（可被独立实现读出）

#### AC-D0.11 · MBR 生成：4 主分区上限必须报错

- **标准**：请求创建第 5 个主分区 ⇒ 明确报错；请求恰好 4 个 ⇒ 成功。
- **验证方式**：`test/test_mbr.c`；打印 `[D0-AC-D0.11] PASS`。
- **负对照/边界**：4 个成功、5 个报错，**两条都跑**（只跑一条等于没有边界）；
  打印 `[D0-AC-D0.11-NEG] PASS`。

#### AC-D0.12 · GPT 生成：可被独立实现读出同样结果

- **标准**：`D0` 生成的 GPT 字节块，由**不引用 `D0` 任何符号**的独立解析器读出的
  分区集合（起始 LBA / 末尾 LBA / 类型 GUID / 唯一 GUID / 名称）与输入描述**逐字段相同**。
- **验证方式**：`test/test_gpt_independent.c`（独立解析器按 UEFI 规范手写偏移，
  含 `"EFI PART"` 签名、`HeaderSize`、`HeaderCRC32` 与条目数组 CRC32 的**独立复算**）；
  打印 `[D0-AC-D0.12] PASS entries=<N>`。
- **负对照/边界**：独立解析器对 `D0` 生成的字节**独立复算 CRC32C** 必须匹配；
  若不匹配判 FAIL（防止"`D0` 自己算错自己验过"）；
  打印 `[D0-AC-D0.12-NEG] PASS`。

#### AC-D0.13 · 保护性 MBR 与 GPT 共存时的解析优先级

- **标准**：GPT 盘上 `LBA 0` 是保护性 MBR（类型 `0xEE`）；`D0` 解析时必须
  **优先识别 GPT**（存在合法 `"EFI PART"` @ LBA 1 ⇒ 按 GPT 解析），
  保护性 MBR 不作为"用户分区"上报。
- **验证方式**：`test/test_gpt.c`；打印 `[D0-AC-D0.13] PASS mode=gpt`。
- **负对照/边界**：构造"保护性 MBR + LBA 1 无 GPT 签名"的畸形盘 ⇒ 必须报错，
  **不得**退化成把 `0xEE` 当普通分区上报；打印 `[D0-AC-D0.13-NEG] PASS`。

### 4.4 对齐

#### AC-D0.14 · 分区起始偏移必须与设备块大小、簇大小对齐

- **标准**：分区起始 LBA 换算成字节后，必须**同时**满足：
  ① 是设备块大小的整数倍；② 是簇大小的整数倍。不满足 ⇒ 明确报错，**不得**自动向上取整。
- **验证方式**：`test/test_align.c`；覆盖组合：块大小 ∈ {512, 2048, 4096} × 簇大小 ∈ {4096, 16384, 65536}；
  打印 `[D0-AC-D0.14] PASS combos=9`。
- **负对照/边界**：每种组合各造一例"差 1 扇区"的越界输入，**必须全部报错**；
  打印 `[D0-AC-D0.14-NEG] PASS combos=9`。

#### AC-D0.15 · 尾部对齐（分区末尾不越界）

- **标准**：分区末尾 LBA 必须 ≤ 盘的总 LBA 数 - 1（GPT 还须 ≤ `LastUsableLBA`，
  且不得覆盖备份 GPT 表区）；越界 ⇒ 明确报错。
- **验证方式**：`test/test_align.c`；打印 `[D0-AC-D0.15] PASS`。
- **负对照/边界**：**恰好等于**上限（必须成功）与**恰好超出 1 扇区**（必须报错），两条都跑；
  打印 `[D0-AC-D0.15-NEG] PASS`。

### 4.5 类型标识作为入参（取向裁定前的正确形态）

#### AC-D0.16 · MBR 类型字节 / GPT 类型 GUID 一律作为入参，本包内不得内嵌字面量

- **标准**：`D0` 的公开接口中，分区类型标识由调用方传入；
  `D0` 源码内**不得**出现 `0x7F` 或 `13073c46-…` 的字面量（测试夹具除外，
  且夹具必须标注"来自 `10-公共约定.md` §3"）。
- **验证方式**：`build.py` 源码扫描 + `test/test_types.c` 接口签名编译期检查；
  打印 `[D0-AC-D0.16] PASS literals=0`。
- **负对照/边界**：扫描器先喂入含 `0x7F` 字面量的合成样本，**必须被抓到**；
  打印 `[D0-AC-D0.16-NEG] PASS`。
- **取向裁定后的动作**：只改 `10-公共约定.md` §3 的常量值，`D0` 源码**零改动**。

### 4.6 块大小（★ 按实测，禁止假设）

#### AC-D0.17 · 块大小从设备自述取值并在分区时记录

- **标准**：`D0` 的卷描述结构体中**必须**含设备块大小字段；该值**只能**来自设备自述
  （由调用方经 `D0` 接口传入），`D0` 内部**不得**出现默认值 512 或任何"按 512 硬推"的路径。
- **验证方式**：`test/test_blocksize.c`；打印 `[D0-AC-D0.17] PASS blocksize=<N>`。
- **负对照/边界**：传入块大小 `0` ⇒ 明确报错（不是"默认 512"）；
  传入非 2 的幂 ⇒ 明确报错；打印 `[D0-AC-D0.17-NEG] PASS cases=2`。

#### AC-D0.18 · 真机锚点：512 与 2048 同机共存

- **标准**：`D0` 必须能在**同一次运行**里正确处理两种不同块大小的设备描述
  （OVMF VVFAT 报 `2048`、NXFS 裸盘镜像报 `512`），互不污染。
- **验证方式**：`test/test_blocksize.c` 构造两个描述对象（块大小 `512` / `2048`）并交错调用；
  打印 `[D0-AC-D0.18] PASS vvfat=2048 raw=512`。
- **负对照/边界**：若实现把块大小存进**全局/静态变量**，交错调用必红；
  打印 `[D0-AC-D0.18-NEG] PASS`。
- **取证出处**：`verify/vm_smoke.py` 串口实录（OVMF VVFAT `block_size=2048`、`logical_partition=1`；
  NXFS 裸盘 `block_size=512`）。

#### AC-D0.19 · 全源码无"按 512 硬推"路径

- **标准**：`D0` 源码内**不得**出现把"设备块"当 512 用的隐式换算，
  也不得出现字面量 `512` 参与块大小相关运算（`NXFS_ST_SECTOR_BYTES` 常量除外，
  且它只能用于**FS 内部扇区单位**，不得用于设备块换算）。
- **验证方式**：`build.py` 源码扫描（模式：`512` 出现在块大小上下文）+ 人工复核清单；
  打印 `[D0-AC-D0.19] PASS hits=0`。
- **负对照/边界**：扫描器先喂入 `blk_size = 512;` 的合成样本，**必须被抓到**；
  打印 `[D0-AC-D0.19-NEG] PASS`。

### 4.7 卷管理动作

#### AC-D0.20 · 创建：重叠 / 越界必须报错

- **标准**：新建分区与既有分区**区间重叠**（半开 `[start, start+count)` 有交集）⇒ 明确报错；
  越界（见 `AC-D0.15`）⇒ 明确报错。
- **验证方式**：`test/test_volume.c`；打印 `[D0-AC-D0.20] PASS cases=<N>`。
- **负对照/边界**：**相邻但不重叠**（前者末尾 == 后者起始）**必须成功**——
  这是最容易把半开区间写成闭区间的地方；打印 `[D0-AC-D0.20-NEG] PASS`。

#### AC-D0.21 · 移除：不存在的分区 / 移除后留下空洞的判定

- **标准**：移除不存在的分区 ⇒ 明确报错；移除后**不自动合并**相邻空洞
  （合并属"空间调整"的职责，见 `AC-D0.22`），但必须**正确报告**空洞的存在与位置。
- **验证方式**：`test/test_volume.c`；打印 `[D0-AC-D0.21] PASS`。
- **负对照/边界**：移除**中间**分区后，两侧分区**必须仍各自完整**（不得被误扩）；
  打印 `[D0-AC-D0.21-NEG] PASS`。

#### AC-D0.22 · 空间调整：扩与缩的边界判定

- **标准**：
  - **扩**：新末尾 ≤ 盘上限（GPT 还须 ≤ `LastUsableLBA`）且不与后续分区重叠 ⇒ 成功；
  - **缩**：新末尾 ≥ 已用空间末尾（由调用方提供的"已用空间"参数给出）⇒ 成功；
    否则明确报错。
- **验证方式**：`test/test_volume.c`；打印 `[D0-AC-D0.22] PASS`。
- **负对照/边界**：缩到**小于已用空间**必须报错（`10-公共约定.md` §16.2 明示"缩需先满足文件系统侧条件"）；
  扩到**与后邻重叠**必须报错；扩到**恰好等于上限**必须成功；三条都跑；
  打印 `[D0-AC-D0.22-NEG] PASS cases=3`。

#### AC-D0.23 · 缩之前的文件系统侧前置条件由调用方负责，`D0` 只校验不越权

- **标准**：`D0` **不得**自行读取文件系统元数据判断"已用空间"；
  "已用空间"必须由调用方传入（通常来自包 `40` 的元数据查询结果）。
- **验证方式**：源码扫描：`D0` 不 include `meta.h` / `journal.h`；
  打印 `[D0-AC-D0.23] PASS`。
- **负对照/边界**：扫描器先喂入 `#include "meta.h"` 的合成样本，**必须被抓到**；
  打印 `[D0-AC-D0.23-NEG] PASS`。

### 4.8 格式化入口

#### AC-D0.24 · 格式化调用既有布局常量，不自己发明盘上布局

- **标准**：`D0` 的格式化入口调用 `20` 的布局接口产出 NXFS 卷结构；

#### AC-D0.25 · 格式化产出的卷可被包 `20` 按偏移打开

## 5. 与 `20` / `A0` 的接口契约

### 5.1 `D0` → `20`：按偏移打开

`D0` 交出的两个事实：

| 事实 | 类型 | 说明 |
| :--- | :--- | :--- |
| **分区起始偏移** | `uint64`（**字节**）或 LBA（扇区，512 B 单位），由 `D0` 在卷描述里**同时给出两者**并保证一致 | `20` 的 `nxfs_sp_user_open` 现从偏移 0 打开整文件 ⇒ 需支持**按分区起始偏移打开** |
| **设备块大小** | `uint32`（字节，来自设备自述） | `20` 的 `sectors_per_block` 分支消费它做换算；**`D0` 不做换算** |

**契约要点**：

1. `D0` **只报告与记录**这两个事实，**不**做"块 ↔ 512B 扇区"的换算（归 `20`，§16.1）；
2. `D0` 保证起始偏移**同时**满足设备块大小与簇大小对齐（`AC-D0.14`），
   使 `20` 无需再做对齐修正；

## 9. 实机安全红线（**死线**，复述 `10-公共约定.md` §15）

> **一句话**：**所有写入只允许发生在镜像文件、内存夹具、QEMU 客户机内部**；
> **真机（宿主物理盘与真实卷）不可碰**。违反＝覆写分区表/引导区，**不可恢复**。

`D0` 特别相关的禁止项：

| # | 禁止 | `D0` 侧的具体表现 |
| :-: | :--- | :--- |
| 1 | 打开/写入物理盘或真实卷（**只读也算**） | `D0` 的测试与工具**不得**出现 `\\.\PhysicalDriveN` / `\\.\X:` / `/dev/sdX` / `/dev/nvmeXnY` |
| 2 | 对真实磁盘跑分区/格式化工具 | **不得**调用 `diskpart` / `sgdisk` / `parted` / `mkfs*` / `format` / `bcdboot` / `bootsect` |
| 3 | 在宿主 OS 安装驱动/过滤层/服务 | `D0` 不做驱动；`A0` 的真实挂载留人工 |
| 4 | 让虚拟机指向物理磁盘 | `D0` 的镜像验收只用**镜像文件** |
| 5 | 改动宿主分区表/引导项/卷标 | `D0` 不碰宿主任何磁盘状态 |

**允许的写入面（仅此三处）**：① `F:\Workspace\**` 下的**镜像文件**；② **内存夹具**；③ **QEMU 客户机内部**。

**不确定某操作会不会碰实机时：不做，先报统筹。**
