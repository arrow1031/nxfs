## 边界（先看这段）

**需要读**：`10-公共约定.md` §6（责任主体与世代号）、§7（提交与可见性）、§8（兼容性机制）；
`nxfs.h` 中的数据面 ring 结构（`nxfs_ring_header_t` / `nxfs_ring_slot_t`）。

**不需要读**：EFI 驱动、跨文件区分发细节、块内预留策略细节。

**关键职责裁定（这一点必须先明确，否则会做错方向）**：

设计稿 §1.2 说"翻译层只做转译，不做策略判断"，但 §6.1（同簇取类型标记）、
§6.3（程序块直读 + 校验）、§6.4（只读元数据缓存与批量失效）都要求翻译层做实际工作。
两者表面冲突。

**裁定**：翻译层按**"保持性能的完整工作量"**处理——它承载热路径所需的**全部**工作，
不只是 ABI 转译。原则应改写为：

> **翻译层不做需要跨事务全局视图的策略。**

缓存失效这种**局部**策略当然要做。因此本包的边界按
**"是否在热路径上"** 划分，而不是按"有没有策略"划分。

## 关键设计点

### 1. 缓存一致性是正确性契约，不是优化

**最重要的认知**：缓存陈旧不是"性能问题"，而是**正确性问题**。因此：

- **缓存只缓存已提交事务的元数据**（`§6.4`）。
- 卷的 `mounted_at_seq` 是**全局基准点**，用于判断"整体视图是否过时到需要重整"，
  **不用于逐个条目校验**（那是世代号的职责）。
- 校验是**版本比较**，不是匹配清单。

### 2. 世代号式失效 vs 列表式失效

| | 列表式 | **世代号式（采用）** |
| :--- | :--- | :--- |
| 校验方式 | 匹配通知清单 | 比较版本号 |
| 漏收通知 | **永久陈旧** | 下次查询即发现不一致 |
| 重复通知 | 需去重 | 无副作用 |
| 乱序送达 | 可能误判 | 无影响 |
| 重放 | 危险 | 安全 |

因此失效通知**幂等、可丢失、可乱序、可重放**——这把"有序性/原子性"从必须遵守的
契约降级为实现的自然结果。**不要为了实现方便退回列表式。**

### 3. 缓存键必须用最小责任主体，不得用卷或全局事务号

```c
/* 正确：按主体 + 世代号 */
key = (subject.kind, subject.a, subject.b);
valid = (cached_gen == current_gen_of(subject));

/* 错误：全局失效 —— 会把设计目标整体作废 */
valid = (cached_seq == volume.committed_seq);
```

**必须实现的配套**：变更类操作返回的 `affected` 主体集合是**唯一的**精确裁剪依据。
因此本包对 `40`/`50`/`70` 有硬依赖：它们必须回传 `affected`。

### 4. 读路径分级（`§6.3`）

| 路径 | 适用 | 流程 | 延迟目标 |
| :--- | :--- | :--- | :--- |
| **热路径** | 程序块内文件，已缓存元数据 | 翻译层直接读块 → 校验和验证 → 返回 | 寻道 + **微秒级** |
| **普通路径** | 非程序文件，或未缓存元数据 | 翻译层 → 用户态模块 → 读块 → 校验和验证 → 返回 | 寻道 + **0.5–2 ms** |

**"直读块"的含义**：热路径命中时，翻译层**不经过用户态模块**，直接读块并验校验和。
这是本设计声称"程序启动近原生延迟"的机制来源。

**实现纪律**：热路径**不分配**（沿用 `20` 包的做法：调用方提供缓冲区）。
否则"微秒级"目标不成立。

### 5. 数据面：共享内存 ring + 批量提交

热路径**不逐操作 IPC**。正确性前提（见 `10-公共约定` §7）：

1. **只有 `COMMITTED` 的槽位可见**；之前的内容一律不可读——这不是优化，
   是防止读到**撕裂的元数据**。
2. 生产者以 **release** 语义发布 `COMMITTED`，消费者以 **acquire** 语义读取。
3. `acked_seq` **可跳跃**（批量提交允许乱序完成）。

**布局硬约束**（`verify_align.c` 已验证）：

| 结构 | 值 |
| :--- | :--- |
| `nxfs_ring_header_t` | **64 B**（恰好一个缓存行，避免头部跨行） |
| `nxfs_ring_slot_t` | **128 B**（槽位头） |
| 槽位载荷 | **3968 B** |
| 槽位总计 | **4096 B**（整页，便于按页映射） |

槽位大小必须能被槽位对齐整除，否则生产者/消费者**错位**。

### 6. 统一操作外壳

所有操作走同一信封 `nxfs_envelope_t`（**48 B 头** + 变长载荷），
响应走 `nxfs_reply_head_t`（**40 B**）+ 受影响主体列表。

**为什么统一**：热路径不是"另一套接口"，而是同一语义的**零拷贝 + 批量化形态**。
否则"两套语义同步维护"的漂移是必然的。**不要给热路径发明独立语义。**

### 7. 类型标记顺手取（`§6.1`）

父日志条目里带类型标记（普通/程序）。翻译层在**读取子文件夹偏移时，同一簇内**顺手拿到它。

**实现后果**：父日志条目的布局必须是**头部连续**的——偏移与类型标记要在同一簇内，
否则"顺手取"就要多读一簇，收益消失。这条约束会影响 `50` 包的父日志条目布局设计，
**两包需对齐**。

## 常见坑

1. **别用全局 `committed_seq` 做逐条目校验** —— 会退化成失效风暴。
2. **别退回列表式失效** —— 会丧失幂等/可丢失/可乱序/可重放四性质。
3. **`WRITING` 状态的内容不可读** —— 读了会得到撕裂的元数据。
4. **热路径不要分配** —— 会毁掉微秒级目标。
5. **`envelope` 是 48 字节不是 32**（编写期已验证）。
6. **槽位大小必须能被对齐整除**，否则生产者/消费者错位。
7. **不要给热路径发明独立语义** —— 它只是同一信封的加速形态。
8. **`mounted_at_seq` 只用于整体重整判断**，不要拿去逐条目比对。
9. **类型标记要在同一簇内** —— 否则"顺手取"失效，需与 `50` 包对齐布局。
