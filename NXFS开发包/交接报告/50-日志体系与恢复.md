## 4. 边界（最容易撞车的三处）

1. **术语**：`NXFS_SAFEPATH_MAX_DEPTH = 16` 是**契约层**的调用/结构深度；**数据层固定 3 层**。
   说"层"时一律指数据层。
2. **9 B ≠ 8 B**：**父日志条目**（4 + 2 + 1 + 1 + 1 = **9 B**，属本包）与**通用索引条目**
   （4 + 2 + 1 + 1 = **8 B**，见 `10-公共约定` §3）**不是同一结构**，两者都要有，**不得合并**。
3. **同一份文件夹日志里谁的字节谁负责**（开发包"三方分工"表）：
   - **头簇** + **父日志条目** → **本包（50）**；
   - `NXFS_META_OBJ_FOLDER_LOG` 对象的**存在/指针/事务** → `40`；
   - **目录项**布局 → **`70`/`90`**。
   本包**只定位与校验，不解释目录项语义**；边界长度/偏移的**权威在本包头簇**。

2. **需要 ABI 新增/变更**：`nxfs.h` 已冻结（基线 tag `v1.0.1`；当前 **`v1.1.0` / ABI 1.2**，
   为尾部追加的 MINOR）。发现"缺一个必要入口"时，走 API 仓 `CHANGELOG.md` + `10-公共约定` §13.3
   的升版流程，**不要顺手改头文件**；用到 v1.1.0 追加字段时按 §13.4 在预处理期加 ABI 守卫。
3. **磁盘格式相关的新裁定**（4Kn 事件区粒度、格式 v2 任何议题、容量/边界默认值）——须先裁定。
4. **性能口径**：`AC-50.10` 的计时基线（"1–3 分钟"按什么规模、在什么机器上）由统筹给定后再实现。
