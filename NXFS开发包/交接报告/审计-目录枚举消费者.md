## 2. 高危优先摘要（只看这节即可决定是否拦合并）

**结论：主树 `dev/onsite-105`（`01f6c2b`）里有 2 个"高"、3 个"中"的真实缺陷/漂移，外加 1 个跨支线合并陷阱。它们都不是 `dir_enum` 自身的问题，而是"块链把'末块/块 0 = 整目录'的旧不变量打破了，而这几处没跟着改"。**

1. **【高】`40/dir.c:1091/1099/1103` 的 `dir_rename` 仍按"末块 = 整目录"工作。**
   源名活在非末块 ⇒ 假 `NOT_FOUND`；目的名活在非末块 ⇒ 查重落空（`1095`/`1129` 只看 `sdv`/`ddv` 这一块），
   而 `dirview_insert` 只在块内查重（`names.c:250-271`）⇒ **同一目录出现两条活重名条目**（静默破坏命名不变量）。
   对照：`file.c:540`（`file_open`）与 `dir.c:1278`（`dir_link`）都用了全链查重，**只有 rename 漏了**——
   `dir.c:946-948` 的作者注释甚至写了"跨块的**查找**由调用方先走 `dir_chain_find`（`dir_create`/`file_open` 已接）"，
   名单里**没有 rename**。

2. **【高】`40/dir.c:821-841` 的 `dir_remove` 非递归空判只读子目录的块 0。**
   块 0 全墓碑 + 活条目在后续块 ⇒ 误判"空"⇒ 删父条目、子目录链成**孤儿**（不可达、不回收）。
   这条同时暴露 `recursive != 0` 只是跳过空判（`839-843` 无递归删除逻辑），所以"误判空"是唯一一道闸门。

3. **【中】`40/dir.c:1402 + 1405-1415` 的 `dir_set_program_folder` 只在末块找条目** ⇒ 非末块条目假 `NOT_FOUND`，
   硬链接下还可能改错那一条。

4. **【中】证据/文档三处漂移**：`tools/adversarial_probe.c:1004-1023`（诊断只反映块 0）、
   `40/test/test_main.c:3343`（断言在链化目录下恒真、失去鉴别力）、
   `fs-api-design/nxfs.h:1140-1158` + `API-设计文档.md:770/786` + `verify/api-coverage.md:82`（"一页一块"未书面化）。

5. **【中】测试护栏未跟**：`40/test/test_main.c:4015/4137` 仍是 `pages < 64u`（=≤256 条），
   工具侧已抬到 `USE_ENUM_PAGES 4096`（`tools/nxfs_use.c:87`）；"不得再有"类断言是 fail-open。

6. **【中·合并风险】`nxfs-impl-wt-data`（`dev/onsite-102`，HEAD `2469e64`）**：
   其 `40/dir.c:345` 仍是 `more = (cur < dv.used)` 的**旧单块语义**、`meta.h` 里没有 `DIR_CAP_BYTES`/`DIR_ATTRS_PER_CLUSTER`，
   且 `tools/nxfs_use.c:614/1363` 是**硬编码 64 页**。⇒ 若把该支线并进主树，**必须同时**解决
   `dir.c` 的块链冲突**和**这 64 页护栏，否则 `ls`/路径查找在 >256 条目录上静默少看。

**不拦的理由也写清**：变更本身的下游**消费者**（`05` 透传、`tools/nxfs_use.c`、`A0` 适配、`40` 测试）
在分页上**都是对的**（见 §3）；`B0/80/70/90/D0` 根本不消费目录面。
风险集中在 **40 包内部的"末块/块 0"假设**与**文档/测试未同步**上。
⇒ 建议：**不阻断合并**，但 §1 的 A1/A2 应按"必须在本次或紧接的批次里修"处理（A2 更急，因为它静默产生孤儿）。

## 3. "不分页会少看"的**逐处**判定与验证方式

### 3.1 判定方法（判据）
一处调用"会不会少看"只需两个问题：
1. 它是否在 `cursor.more == 1` 时**再次调用**（并把上一页的 `cursor` 回传）？
2. 它是否把"页内条数 < `max_entries`"当成"目录结束"？
