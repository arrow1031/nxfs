# 批次任务书：**未写 extent 记账**（unwritten extent）

> 依据（人类 2026-09-29 指示）："如果哪里做不成，就想想其他文件系统怎么做的 —— 我们设计思路没问题，
> **格式确实野路子**"。本任务书就是照 XFS/ext4 的**成熟做法**把"野路子"补成常规做法。

## 1. 问题（已由插桩定位，见《今晚收口报告》§13）

30-存储抽象层/storage.c 的 st_write_cluster_span() 做**簇内部分写**时走"读-改-写"，前置检查是：

    该簇 **CRC 有效** 或 **全 0**（视为"未写入"） ⇒ 否则判 CORRUPT

而**新分配的簇**在真实介质上残留旧内容（CRC 无效且非全 0）⇒ 拒绝 ⇒
凡是要写"8 字节块头"这类部分写的路径（文件块头、目录项、格式化结构、快照表）**都会挂**；
镜像新建文件全 0 ⇒ 长期掩盖。当前**临时**修法是在 40 层对"本文件新分配的段"逐簇调用

xfs_st_cluster_init() 写全 0（已验证：脏镜像 4/64 KiB 簇 + 66 MB ISO 全绿 ✓），
但它是**逐簇一次额外整簇写** ⇒ 大卷/真盘上过慢（实测：分配器级下沉后 8 GiB/64 KiB 超 150 s ✗）。

## 2. 常规做法（照抄 XFS / ext4）

| 系统 | 做法 |
| :--- | :--- |
| **XFS** | unwritten extent：extent 状态位标记"已分配但未写" ⇒ **读返回零**，**写时转写实**（无需先读盘） |
| **ext4** | unwritten extent（extent 标志位）+ i_disksize 语义 ⇒ 同理 |
| **ZFS / btrfs** | 逻辑块映射表 + "hole/未写"语义 ⇒ 读洞返回零，写不触发 RMW |
| **通用块层** | "未写"是**逻辑状态**，不是"盘上恰好是 0" —— 这正是我们当前判据的野路子所在 ✗ |

⇒ 结论：**"未写"必须由文件系统记账，而不是靠"从盘上读出全 0"来判定** ✓。

## 3. 设计（最小改动，两层）

1. **30 层**新增"未写窗口"记账（本层自持，不外借缓冲）：
   - 
xfs_st_mark_unwritten(handle, first_cluster, count)：登记一段"已分配未写"；
   - 
xfs_st_unmark_unwritten(handle, cluster)：写实后清除；
   - st_write_cluster_span() 的信任检查改为：
     ① CRC 有效 ⇒ 直接改（现状 ✓）；
     ② **命中未写窗口** ⇒ 把 scratch 置零后继续（**不读盘** ✓）；
     ③ 全 0 ⇒ 同现状（格式化态 ✓）；
     ④ 其余 ⇒ 仍严格判 **CORRUPT** ✓（完整性判据**不放松** ✓）；
   - 记账容器：ctx 内一段**有界**的 run 列表（如 64 项）或位图分片；溢出时**回退为"写实前先读"**（保守 ✓）。
2. **40 层**：
xfs_meta_alloc_clusters() 分配成功后 mark_unwritten（覆盖文件/对象/目录/快照/格式化 ✓
   全部分配者 ✓），并**撤掉** ile.c 里那份逐簇 
xfs_st_cluster_init（避免额外 IO ✗）。

- 每一处以"**有牙用例**"配对（未写窗口溢出、真损坏仍报 CORRUPT）✓；

## 6. 追加（2026-09-29 08:3x，真盘实测）：**每块 3 次 IO ⇒ 66 MB 需 ~270 s**

真盘（老盘 Disk 0，4 KiB 簇）实测：格式化 D0_MKFS_OK ✓，但 **66 MB ISO 在 240 s 内未写完** ✗。
与机制核算一致 ✓：

| 每 4 KiB 文件块的介质 IO | 次数 | 原因 |
| :--- | :--- | :--- |
| 块头（8 字节）RMW | 2（读+写） | 簇内**部分写** ⇒ 必须先把簇读上来（st_write_cluster_span ✓） |
| 载荷（4088 字节，整载荷 ✓） | 1 | 走快路 ⇒ 不读 ✓ |
| **合计** | **3** | 66 MB ⇒ 16,900 块 ⇒ **约 6.7 万次 IO** × ~4 ms ≈ **270 s** ✓ |

### 常规做法（照 XFS/ext4 的"整块写"）：**凑齐整簇、一次写** ✓

- 在 40 层准备**一个专属的簇缓冲**（**不是** obj_scratch ✗ —— 那是共享暂存，借了会毁事务，今晚已踩过 ✓）；
- 把 **[8 字节块头][载荷][尾部补零至 payload_bytes]** 在缓冲里拼好 ⇒ **一次** 
xfs_st_cluster_write
  （或 
xfs_st_write 且 len == payload_bytes ✓）⇒ **无读、无 RMW** ✓；
- ⇒ 每块 **1 次 IO** ⇒ 66 MB ≈ **1.7 万次 IO** ≈ **17 s** ✓（**16 倍**改善 ✓），且**正确性不再依赖
  "RMW 信任检查"** ✓（与第 5 节的 unwritten extent 一起，把"野路子"补成常规做法 ✓）。

### 配套（都必须做，不许只做一半 ✗）

1. 簇缓冲必须是**本层自持**且有**容量校验** ✓（参照 cow.c 对 obj_scratch_bytes 的校验写法 ✓）；
2. **最后一个块**（used < payload_bytes）要**显式补零**到 payload_bytes ✓，否则又退化成部分写 ✗；
3. 回归：脏镜像（全 0xAA）× 4/64 KiB 簇 × 8 MiB 与 **66 MB ISO** ⇒ **SHA-256 MATCH** ✓；
   	ools/use_e2e.py 保持 **52/0** ✓；erify/run_all.py 保持**全绿**（12 包 pass ✓）；
4. 真盘复测（老盘 Disk 0，已授权）：**66 MB ISO 应在 ~30 s 内**完成并 SHA-256 MATCH ✓ —— 这是本轮
   "从 270 s 到 30 s"的**验收数字** ✓。
