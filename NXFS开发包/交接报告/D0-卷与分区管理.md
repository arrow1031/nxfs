# `D0` 卷与分区管理 · 开工简报（2026-09-26 立项）

> 归属：**独立成包**（上级 2026-09-26 令：「考虑把分区管理（包括但不限于创建移除格式化空间调整等
> 任何文件系统都能做到的管理）职责补到某个包里，如果不方便补到包里就独立实现」）。
> 规范依据：[`10-公共约定.md` §16](../10-公共约定.md)（块大小契约 + 归属裁定 + 分期与验收）。

## 一、为什么要独立成包（权责裁定，按 `COORDINATION.md` §5.9 六条判过）

事实（**规范层原有的空白，不是谁的实现缺陷**）：

| 事实 | 出处 |
| :--- | :--- |
| **没有任何代码写分区表** —— `NXFS_MBR_TYPE_BYTE` / `NXFS_GPT_TYPE_GUID` 只以**常量**形式存在于 API、文档、以及总账的 `fs_type_guid` 字段 | 交接报告 · 虚拟机测试就绪判断 §② |
| 「分区表 + **按偏移打开**」被刻意缓为 **L3/实机前置**；`nxfs_sp_user_open` 目前从**偏移 0** 打开整文件 | 同上 · 路径修正 |
| **块大小的实测报告无人接收**：`nxfs.h` 里没有任何块大小 / 分区字段；真机上同一时刻就有 `512` 与 `2048` 两种设备块大小 | grep `nxfs.h` + `vm_smoke` 串口实录 |

**逐条判**：

1. 归 `20`？ **否** —— 20 已冻结，且其权责是"兼容层与安全路径"（L4 入口 + 安全 IO + 盘上布局常量），
   不是"磁盘管理"。硬塞进去会同时破坏冻结面与权责独立性。
2. 归 `B0`？ **否** —— 它是**只读**驱动，分区表写入与"调整空间"在定义上做不了。
   （按 §5.9 判据 4：**这不是 B0 的错**，是没给它这份活。）
3. 归 `A0`？ **部分** —— `A0`（Windows 集成层）是 **OS 集成面**，是"**原生验收**"的承担者；
   但把分区表读写也塞进去，会让它同时承担"OS 侧集成"与"盘上分区表格式"，权责不独立。
4. ⇒ **独立成包**：`D0` 拥有**唯一一份**分区/卷管理实现，**工具面与原生面共用**它
   （符合 `10-公共约定.md` §14「一个源只有一个所有者」，**不为两条路各写一套**）。

## 二、职责边界（`D0` 拥有什么 / 不拥有什么）

**拥有（唯一实现点）**：

- **分区表读写**：MBR（类型字节 `0x7F`）与 GPT（自定义 GUID `13073c46-…`）的**解析与生成**；
- **卷管理动作**：**创建 / 移除 / 空间调整**（调整含"扩"与"缩"的边界判定，缩需先满足文件系统侧条件）；
- **格式化入口**：调用方给出几何（簇大小等）→ 产出可挂载的 NXFS 卷（**不自己发明盘上布局**，
  布局常量归 `20`/`30`/`40`/`50` 的各自格式头）；
- **块大小的实测与记录**：从**设备自述**取块大小（UEFI `BlockIo.Media.BlockSize` / 宿主平台对应报告），
  **在分区时记录**下来，并把"分区起始偏移 + 设备块大小"交给 `20` 去按偏移打开。

**不拥有**：

- 不拥有 NXFS 的**盘上布局常量**（分别归 `20`/`30`/`40`/`50` 的格式头）；
- 不拥有**设备 IO 的块大小换算**（归 `20` 的 `sectors_per_block` 分支）—— `D0` 只**报告与记录**事实；
- 不拥有 OS 侧的可见性/集成（归 `A0`）；
- **不碰宿主物理盘**（`10-公共约定.md` §15 死线）：一切写入只发生在 `F:\Workspace\**` 的**镜像文件**内。

## 三、验收口径（**分期，且工具面不算验收**）

| 阶段 | 内容 | 验收 |
| :--- | :--- | :--- |
| **S1** | `D0` 实现分区表读写 + 建/删/调 + 格式化；由 `tools/` 消费（镜像文件内） | ❌ **只算中间成功**（上级明令："需要工具的部分成功，不能完全认可"） |
| **S2** | 包 `20` 加性扩展：**按分区起始偏移打开** + 按**设备自述**块大小换算；`D0` 接入 | ❌ 中间（S3 的前置） |
| **S3** | **原生**：在系统**磁盘管理**里像原生文件系统那样创建 / 移除 / 调整 / 格式化 NXFS 卷（`A0`） | ✅ **验收终点** |

## 四、待上级点头的**理论级修正**（落地前不动常量）

现有设计**刻意**让 Windows/Linux **认不出** NXFS（MBR `0x7F` + 随机 v4 GUID），目的是
"**不自动挂载、不提示格式化**"。而 S3 要求系统**认得出并管得了** NXFS —— 二者方向相反。

⇒ 按上级令"验收终点是原生"，`0x7F`/随机 GUID 的**取向须修正**为
「**被正确识别为 NXFS、且不被误当成 LVM（`0x8E`）/未格式化**」。
**该修正触动冻结约定（README 硬性约束表 + `10-公共约定.md`），须上级明确点头后落地。**

## 五、第一批建议（S1 的最小切片）

1. **只做"读 + 写"分区表这一件事**，形态为**纯逻辑层**（不碰设备、不碰几何换算）：
   入参给"盘的总扇区数 + 设备块大小 + 要建/删/调的分区描述"，出参给"分区表字节 + 校验"；
2. 同时提供**解析**方向（从字节还原分区描述），供 `20` 的"按偏移打开"与真机取证使用；
3. **边界必须有牙**：重叠分区 / 越界 / 超 4 个主分区（MBR）/ GPT 备份表不一致 / 块大小不被支持
   —— 每条都要有能红的负对照；
4. 真机取证：在 QEMU+OVMF 的**镜像文件**上建分区 → 由 `20` **按偏移**读出 NXFS 卷 → 打印
   `块大小实测值` 与"分区起始偏移"两个事实。
