## 2. 失败项定位（代码级）

红项来自 `verify/adversarial_e2e.py` 第 2b 节（行号为 `ffdc850`）：

```python
img, _ = fresh_volume("fill")
p = probe("rw", img, "--cluster", str(CLUSTER), env_extra={"ADV_SKIP_SLOT_TEST": "1"})
check(p.returncode == 0, "填到满探针全绿（写路径的 NO_SPACE/不越界断言）", ...)
```

一次调用产生**两条失败行**（`probe()` 在 `rc != 0` 时额外发一条 `check(False, ...)`），
故红跑是「65 通过 + 2 失败 = 67 项」而绿跑是「66 通过 + 0 失败 = 66 项」——
**恰好一项 check 从绿翻红**，其余逐项一致。这证明是单点瞬时失败，而不是结构性差异。

该探针 D 段共 12 项（D01/D02/D03/D04/D03b/D05/D10/D11/D12/D06/D07/D08）。
其中**只有 `D02`** 的期望是"填满循环最终必须返回 `NO_SPACE`"：

```c
/* tools/adversarial_probe.c:1064-1068 */
if (rc == NXFS_ERR_NO_SPACE) { ok("D02", ...); } else { bad("D02", "期望 NO_SPACE", d); }
```

## 3. 最可能的机制（代码可证，但**未复现**）

`adversarial_probe` 走 `nxfs_sp_user_open()` → `nxfs_sp_win_io()`，后者用
**`GetOverlappedResultEx(h, &ov, &cgot, (DWORD)timeout_ms, FALSE)`** 做**逐块硬超时**：

```
20-兼容层与安全路径/safepath_platform_user.c:190-201
    /* 等待至多 timeout_ms；到点即取消——硬性超时的落点（逐块计时）。 */
    if (!GetOverlappedResultEx(h, &ov, &cgot, (DWORD)timeout_ms, FALSE)) {
        if (err == WAIT_TIMEOUT) { *timed_out = 1; return NXFS_ERR_TIMEOUT; }
```

`timeout_ms` 默认 = `NXFS_SAFEPATH_IO_TIMEOUT_MS` = **100 ms**（`fs-api-design/nxfs.h:208`）。
⇒ 宿主某一次 IO 抖动 > 100 ms ⇒ `NXFS_ERR_TIMEOUT` ⇒ 填满循环拿到的不是 `NO_SPACE`
⇒ **D02 单点翻红**（其余 11 项不依赖"填满那一击"的返回码，故仍绿）。

**旁证（本仓自己的历史记录）**：`ffdc850` 的提交信息里已记过同一条路径 ——

> "真因记录：ftruncate/fsutil createnew 建的是未实体化文件 ⇒ 首次高位写要同步零填充
> ⇒ 超 IO 超时（TIMEOUT(-3)）。"

**诚实标注**：机制是代码可证 + 现象自洽，但**我没有复现出那次红**（人工造压力的 3 次仍绿）。
因此"就是 100 ms 超时"是**最可能**的成因，不是已证实；未复现的红不排除其他瞬时原因。

## 4. 门禁自身的报告缺陷（真缺陷，建议修）

`verify/gate_all.py`：

- `:71` `def run(title, args, cwd=ROOT, tail: int = 25)`
- `:119` 对 `adversarial_e2e.py` 用 `tail=30`
- `:80-85` **只在失败时保留最后 30 行**：

```python
detail = "\n".join(lines[-tail:]) if not ok else ""
...
print("       --- 失败尾部 ---")
```

而该脚本的失败项（D 段）位于输出**中段**，最后 30 行是**末尾的真盘护栏段** ⇒
日志里只剩「探针 rw 报告了 1 项失败（见上面的逐项输出）」，**而"上面"已被丢掉**。
⇒ **门禁会报红，但不告诉你红在哪一项。**

**建议**（需人类裁定，且**不得削弱任何判据**）：
1. 失败时把整段 stdout 落到单独文件（或在同一次输出里保留所有含 `BAD`/`失败`/`FAIL` 的行），而不是只留尾部 30 行；
2. 对"逐块硬超时"这类**瞬时**失败，在探针侧**如实区分** `TIMEOUT` 与 `NO_SPACE`
   （`D02` 的 detail 里已经会打出真实返回码，故只要输出不被截断就能自证），
   并考虑有界重试（**重试必须记账并可见**，不许把重试洗成"一次就绿"）；
3. 是否放宽/重试属**人类裁定**；在裁定前，本次的处置是"重跑取得干净记录 + 立此存照"。
