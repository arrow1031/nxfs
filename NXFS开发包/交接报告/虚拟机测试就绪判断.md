# 就绪判断 · 正式虚拟机测试（而非合跑）

> **问题**：现在能不能从"合跑"（`verify/joint/` 同二进制 + 内存夹具）升级到**正式虚拟机测试**？
> **结论（2026-09-26 更新）**：**完整 L2 仍不具备**——唯一剩下的硬前置是 **`B0` 驱动本体**；
> 但**中间台阶 L1（宿主侧真实镜像端到端）与 L2 前置冒烟（真固件 × 真块设备，只走包 20 的链）都已跑通**，
> 而前置冒烟还**抓到并修掉了一个只有真固件才看得见的包 20 缺陷**（见 §8）。
> ⇒ **L2 的剩余风险面已收敛到 `B0` 自身**（协议实现 + 三阶段状态机）。
>
> 判断依据：实现仓现状（`git`）、`NXFS开发包/`（各包 AC 与环节表）、
> 设计稿 **§12.3**（"调试：QEMU + OVMF"、"框架：EDK II"）与 **§12.4**（三阶段引导）。
> **一切以仓库现状为准**；本文只做判断与前置清单，不含"我已实现"的声明。

## 3. 好消息：三件"看似缺"的其实已具备

1. **20 已有 UEFI 平台包装且已交叉验证**：`safepath_platform_uefi.c`，六阶段里含 **freestanding 编译**与**对侧平台（`x86_64-uefi`）交叉链接**——`B0` 的地基在。
2. **"真实 OS 文件即设备"已实现**：`nxfs_sp_user_open(path_utf8, …)`（普通文件/卷设备，带 `read_only` 标志与硬性超时语义；Windows 侧 `FILE_FLAG_OVERLAPPED`），并已有 **18 项真实文件端到端测试**。⇒ **L1 的工具只需接线，不必新造设备**。
3. **格式化入口已存在**：`nxfs_meta_ledger_format(ctx, req, …)`（40）。⇒ L1/L2 的镜像可以用**自家代码**格式化，而不是手工拼字节。

> **补充（对 L2 的减负）**：§12.4 **阶段一只走 20 的安全路径**（总账 → 引导文件表 → 内核文件），
> **不需要** 70/90 的目录项语义、也不需要 60/写入路径。所以 "B0 + 镜像工具 + 工具链" 就能跑通
> L2 的第一条验收，**不必等环节2 做完**。

## 4. 最小前置清单（按建议顺序）

> **路径修正（L1 落地后，2026-09-26）**：原清单里的"整盘镜像 / 分区表写入"**对 L2 不是必需的**——
> QEMU 的 **VVFAT**（`-drive format=raw,file=fat:rw:<宿主目录>`）能把宿主目录直接当 FAT 盘给固件，
> 于是 ESP 免造；NXFS 镜像作**第二块裸盘**，EFI 应用经 `EFI_BLOCK_IO` 直读。
> ⇒ 分区表 + "按偏移打开"（`nxfs_sp_user_open` 目前从偏移 0 打开整文件）**属 L3/实机前置**，不提前造。
> 决策与理由记在 `nxfs-impl/tools/README.md` 的 **D1**。

| # | 前置 | 归属 | 状态 |
| :-: | :--- | :--- | :--- |
| 1 | **宿主镜像工具**（L1 载体） | 共享工程工具（底层/统筹） | ✅ **完成**：`tools/nxfs_image`（format / info / verify / layout）+ `verify/image_e2e.py`（**29 项 / 0 失败**，含零写证明与两条负对照），已并入 `run_all.py` |

## 5. 建议路径（省时间）

```
L0（已上线）→  L1 宿主真实镜像端到端 ✅  →  L2-pre 真固件前置冒烟 ✅  →  L2 完整（B0 流）  →  L3（分区表 + 按偏移打开 + A0）
                                                      ↑ 已由统筹直接做（不等 B0）        ↑ 环节3，当前唯一阻塞
```

**为什么不先做 L2**：L2 的三项缺口中，`B0` 是量最大的一项；而 L1 已把"真实镜像"这条链验穿
（format/mount/定位在**真文件**上成立，而不是内存夹具，且证明了只读零写）。
**L2-pre 又把固件侧那条链验穿**（真 OVMF × 真 `EFI_BLOCK_IO` × 真镜像，且含降级负对照）。
现在 L2 的风险面**只剩 `B0` 自己**——这正是 L1 与 L2-pre 的价值。

## 6. 三点裁定的结果（2026-09-26）

## 8. L2 前置冒烟已产出的实质结果（写给 `B0` 流）

冒烟脚本本身就是"最小版的 `B0` 链接试验"。它跑通之后，除了证明链路成立，还**留下了三条对 `B0` 直接有用的东西**：

| # | 结果 | 对 `B0` 的意义 |
| :-: | :--- | :--- |
| 1 | **包 20 的 UEFI media 布局缺陷已修正**：`nxfs_efi_block_io_media_t::last_block` 原为 `u32`（偏移 20），规范的 `EFI_BLOCK_IO_MEDIA.LastBlock` 是 `EFI_LBA`＝`u64`（偏移 **24**）⇒ 真固件里容量恒读成 1 块，`kernel_read` 判 `NXFS_ERR_INVALID_ARG`，**固件读不到内核文件** | `B0` 若自己抄一份 media 结构体，会**重犯同一个错**。现在：包 20 已修，且新增**金标准字节镜像**用例防回归。判定手段是"同一 `media` 指针两种解释对照"（实测 262144 块 vs 1 块），**不是读规范文本** |
| 2 | **`__chkstk` / `_fltused` 两个链接符号**：包 20 的 UEFI 包装有 4 KB 栈缓冲 ⇒ x64 ABI 下引用 `__chkstk`；UEFI 目标链接还需 `_fltused` | 包 20 的阶段 4 **只编译不链接**，所以它自己的验收看不见这两条。`B0` **必须真链接一次**（EDK II 的 `BaseLib` 自带实现；或由包 20 评估把该缓冲改为静态） |
| 3 | **判据形态**：标记式（`NXFS-VM-PROBE OK/FAIL <原因>`）+ **必须有牙的负对照**（篡改主总账 → 固件里必须看到 `from_secondary=1`，且降级后链路仍通）；**QEMU 退出码不参与判定** | `B0` 的 VM 验收照此形态写：固件自己会退出，退出码不可靠；只读驱动也要有降级负对照 |
