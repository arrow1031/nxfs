## G. 【案例·2026-09-29】"懒分配文件不是磁盘"：CORRUPT 的真凶是测试造镜像方式

## §H 红线：**魔数打点绝不能写在物理 LBA0**（2026-09-29 事故 + 机制）

**现象**（人类报告）：用 Disk 1（TOSHIBA，GPT，6 个真分区，D:–L: 都在上面）做范围测试后**重启，盘符丢失**。

**机制（已定位到行）**：	ools/nxfs_physdisk.c:549
`c
rc = dev->write_sectors(dev, 0u, 1u, wbuf, ...);   /* probe：往 lba=0 写魔数 */
`
该调用在**原始物理设备句柄**上执行；日志顺序证明它**先于**偏移视图建立：
``
media: PHYSICAL(真盘整设备)      ← 原始句柄
probe: write lba=0 ... MATCH     ← 写进了**物理 LBA0 = 保护性 MBR 起始 16 字节**
偏移包装失败（rc=-20 ...）        ← 偏移视图这才失败
``
⇒ 在**范围/单分区模式**下，只要偏移包装尚未成功（未对齐等，实测 -20），probe 就会落在**物理 LBA0** ✗。
（本次只覆盖 LBA0 前 16 字节的**引导代码区**；分区项表在偏移 446、签名在 510，均未被改，GPT 本体未被碰 ⇒ 可修复，人类已处理。）

**硬红线（新增，优先级最高）**：
1. **probe 禁止在物理 LBA0 落笔** ✗ —— 打点必须落在**授权范围之内**（如 ange_start + 1 簇），或
2. --partition / --range-only 模式下**默认关闭魔数打点** ✓（范围模式本就由**范围护栏**给出证明：范围落在同一分区/未分配段内 ⇒ 已足够），或
3. 若仍要打点 ⇒ 必须**先**成功建立偏移视图、**再**在**视图内**的合法位置打点 ✓；视图失败时**一个字节都不许写** ✓。
4. **任何物理盘上的"零写核身"必须真正零写** ✓：--identify-only / --verify-only 已是零写 ✓，这条要与 probe 的上述规则一起回归 ✓。

**教训（进"我们做过的事"）**：*"自证写路径可用"的自检，本身就是一次写入* —— 因此在**别人的数据盘**上，任何自检都必须先问清楚"它到底写在哪个 LBA" ✗。
