# 大虚拟环境建设方案（Windows / Linux 完整系统客户机）

> **上级授权**（2026-09-27）：「真机这边可以进一步装『**有完整系统的大虚拟环境**』（win 的和
> Linux 的都做）来排除问题，且大虚拟环境可以**生成较大的虚拟磁盘文件**」；
> 另：「**SSD 这边别动**，把 **HDD 这边**先收拾好」。
> **用途**：把原先"留人工"的真机项（**真实挂载** / **实机引导** / **弱内存序**）
> 搬到可控的完整系统客户机里做，并让 `E1` 的端到端小链在客户机里跑通。

## 0. 红线（与 `10-公共约定.md` §15 一致，**不因"虚拟环境"放宽**）

只写 `F:\Workspace\vm\**` 下的**镜像文件**与 **QEMU 客户机内部**；
**不**打开物理盘/真实卷、**不**装宿主驱动或服务、**不**碰 BattlEye/BEDaisy；**一次只起一个 guest**。
客户机镜像与快照全部落在 `F:\Workspace\vm\`（该目录在超项目 `.gitignore` 的 `/*` 之下 ⇒ 不会被提交）。

### 2.1 无人值守里三个**必须**的点（都是踩出来的）

1. **绕过 Win11 硬件门槛**：宿主无 TPM ⇒ 在 `windowsPE` 的 `RunSynchronous` 里写
   `HKLM\SYSTEM\Setup\LabConfig` 的 `BypassTPMCheck` / `BypassSecureBootCheck` / `BypassRAMCheck` /
   `BypassCPUCheck` / `BypassStorageCheck` / `BypassDiskCheck`。
2. **绕开"必须联网登录微软账户"**：`BypassNRO` 必须写在 **`specialize` 阶段**（早于 OOBE）；
   写在 `FirstLogonCommands` 里**太晚**，安装会卡在"让我们连接到网络"。
3. **磁盘顺序**：`autounattend.xml` 里 `DiskID 0` 指的是**命令行里先出现的那块盘** ⇒
   `vmctl.ps1` 把 `qcow2` 排在 vvfat（无人值守盘）**之前**，否则 Setup 会去格式化无人值守盘。

### 2.2 已经踩过的坑（避免重犯）

| 坑 | 现象 | 处置 |
| :--- | :--- | :--- |
| **WHPX 在 AMD 上多 vCPU 不稳（本轮最硬结论）** | 装到一半窗口显示「**已暂停**」：`info status` = 裸 `paused`、三块设备**无 io-error**、`system_wakeup` 说"不在挂起态"、monitor 的 `cont` **无报错但唤不回**；再试一次直接**退出**。`qemu.err.log` 里是 **`qemu: WHPX: Unexpected VP exit code 4`** 重复 6 次（= 6 个 vCPU 量级）后 abort | ① **vCPU 降到 2**（本轮处置，已跑通）；② 仍崩则退 **`-accel tcg`**（慢但稳）；③ **前提：QEMU 的 stderr 必须落盘**，否则无从诊断 |
| **QEMU 的 stdout/stderr 没落盘** | 第一次"已暂停"只能靠猜 | 载体启动时重定向到 `win11/qemu.out.log` / `qemu.err.log`（这条改动直接揪出了 WHPX 那一行） |
| **重定向的副作用：QEMU 变成该次工具调用的子进程** | 现象：我的调用一结束 **QEMU 就被连带收走**（"你一停它就关"） | 把启动放进**后台作业**并在作业里**守候**（`while (Get-Process qemu-system-x86_64) { Start-Sleep 15 }`）⇒ 作业活着 = QEMU 活着 |
| **`-Show` 必须配 `-WindowStyle Normal`** | 用 `Hidden` 启动时 GTK 窗口 `MainWindowHandle=0`，人**看不到也点不到** | `-Show` 分支用 `Normal` |
| **用 virtio 给 Windows 装系统** | 分区页**看不到任何盘**（Setup 无 virtio 驱动） | 用 **SATA/IDE**（q35 默认 `ahci`） |
| **首次引导 OVMF 不认 CD** | 落到 `Shell>`（而 `FS0:` 其实**正是** El Torito 的 FAT 镜像，里面有 `\efi\boot\bootx64.efi`） | 从 Shell 手动 `fs0:` + `\efi\boot\bootx64.efi`（已做成 `-Action bootcd`）；`bootindex` 只能挂 `-device`，且 q35 默认那个空 CD 会占 `ide.0/ide.1` ⇒ 我们的 CD 挂 `bus=ide.2` |
| **`autounattend.xml` 被 Setup 忽略** | `wmic logicaldisk` 显示 vvfat 是 **DriveType=3（固定盘）**；Setup **只在可移动介质**上找答案文件 | 改挂 **USB 移动盘**（`-device usb-ehci` + `usb-storage`），或直接手动（本轮选后者：`Shift+F10` 打 `LabConfig` + 手动点 GUI） |
| **sendkey 的 `%` 没映射** | `for %v …` 变成 `for v …`，cmd 报"此时不应有 v" | `%` → `shift-5`（已补进 KEYMAP） |
| **`fat:ro:` 不被该 QEMU 支持** | `Block node is read-only` | vvfat 保持 `rw`（该目录只放 `autounattend.xml`） |
| `.ps1` 存成**无 BOM 的 UTF-8** | PowerShell 5.1 按 GBK 读 ⇒ 中文字符串把引号拆开 ⇒ 成片语法错 | **`vmctl.ps1` 一律 ASCII 文案** |
| XML **注释里含 `--`** | `[xml]` 解析直接失败（"XML 注释中不能包含 --"） | 注释里不用 `--`（用 `:` / `—`） |
| **`cluster N used more than once`（qcow2 写被拒）** | 看着像镜像损坏、客户机变慢；但实测 `qemu-img check` 报 **`No errors were found on the image`** ⇒ 只是 **QEMU 拒绝了一次双分配**，客户机会重试，**镜像没坏** | **处置判据**：先 `qemu-img check <盘>`（默认只读）——① 报 `No errors` ⇒ **别 `-r all`、别重装**，继续等；② 报真错误 ⇒ `qemu-img check -r all` 修；③ 修不动 ⇒ 重建盘重装（TCG 下约 1–2 h） |
| 缺 `swtpm` | 无法提供 TPM 2.0 | 用 LabConfig 绕过（见 2.1 第 1 条） |

### 2.3 载体脚本用法（`F:\Workspace\vm\vmctl.ps1`，ASCII 文案）

```powershell
cd F:\Workspace\vm
.\vmctl.ps1 -Action create  -Guest win11 -SizeGB 128                        # 建盘 + 拷 OVMF vars
.\vmctl.ps1 -Action install -Guest win11 -Iso I:\Win11_23H2_...iso           # 无人值守安装（先试 whpx，退 tcg）
.\vmctl.ps1 -Action status  -Guest win11                                     # 进程活着吗 + 串口尾部
.\vmctl.ps1 -Action shot    -Guest win11 -Name step1                         # screendump → PNG（可读图审阅）
.\vmctl.ps1 -Action key     -Guest win11 -Keys shift-f10                     # sendkey 打键（无 GUI 也能操作）
.\vmctl.ps1 -Action mon     -Guest win11 -Cmd "info status"                  # 任意 monitor 命令
.\vmctl.ps1 -Action stop    -Guest win11                                     # quit
```

> `-Action shot` 用**捆绑 Python**（`Pillow 12.3.0`）把 PPM 转 PNG：
> `F:\DSH\dsh-home\dsh-runtimes\dsh-primary-runtime\dependencies\python\python.exe`。
> 安装过程中若无人值守文件被拒（例如镜像索引 1 不是期望版本），就用 `shot` + `key` 手动走完。

## 3. Linux 客户机

| 项 | 值 |
| :--- | :--- |
| 镜像 | **本机没有任何 Linux ISO** ⇒ 需要**下载一个小镜像**（建议 `Alpine virt` ~60 MB 或 `Debian netinst` ~700 MB；也可用 Debian/Ubuntu **cloud image** + cloud-init） |
| 客户机盘 | 同 Windows：qcow2 稀疏，按需 64–256 GB |
| 用途 | ① POSIX 面语义（`A0` 的 POSIX 映射）；② **弱内存序**那条线：用 `qemu-system-aarch64` + `edk2-aarch64-code.fd`（`.tools/qemu/share/` 已有）跑 **aarch64 Linux**，为 `AC-80.7` 并发半 与 `AC-80.8`（release/acquire）提供**非 x86 载体** —— 这是原先登记为"必须 ARM / 人工"的那两项 |

## 4. 重启后的恢复清单（turnkey）

1. 校验加速生效：`qemu-system-x86_64.exe -accel whpx -machine q35 -m 256 -display none -serial null`
   能正常起来（若报 `WHPX: ...` 失败，退回 `-accel tcg` 并如实登记）。
2. `.\vmctl.ps1 -Action install -Guest win11 -Iso I:\...iso` → `status` / `shot` 轮询到 OOBE 完成。
3. 装完后 `-Action run` 进系统，截图确认桌面；随后把 NXFS 的测试件按客户机可用方式送进去
   （vvfat 数据盘 / 客户机内再从宿主拉取诸版本都行）。
4. Linux 客户机：下载小镜像 → 同法装 → 再把 `aarch64` 载体那条线接上。
5. 客户机内跑 **E1 端到端小链**（挂载 → 建目录 → 写文件 → 提交 → 读回 → 查询）。

## 5. 与"人工项"的对应关系（原 A 组 → 现在有了载体）

| 原人工项 | 大虚拟环境里的做法 |
| :--- | :--- |
| `AC-A0.8` 真实挂载（装驱动 + 真实卷） | **Windows 客户机**内装 `A0` 驱动 + 挂载虚拟 NXFS 盘；客户机内部"装驱动"不违反红线（不动宿主） |
| `AC-A0.6` 真机半 / `AC-A0.7` 卷侧半 | 同一 Windows 客户机 |
| 实机引导（`B0` 三阶段） | Windows/Linux 客户机均可用 OVMF + 真 NXFS 镜像做**真固件**引导 |
| `AC-80.7` 并发半 / `AC-80.8` 弱内存序 | `qemu-system-aarch64` 上的 Linux 客户机（**非 x86 载体**） |
| E1 端到端小链 | 两个客户机里都跑一遍（Windows 走 `A0`，Linux 走 POSIX 面） |
