## 边界（先看这段，避免读无关内容）

**需要读**：`10-公共约定.md`；`nxfs.h` 中的 `nxfs_safepath_v1_t` 与 `nxfs_safe_*` 结构体。

**不需要读**：元数据引擎、日志体系、跨文件区、文件块分配、翻译层。安全路径**不依赖它们**——
这是它能在 UEFI 固件与早期内核中独立成立的前提。

**也不要做**：不要为安全路径引入任何策略（缓存、分配、调度、重试策略配置）。
需要这些的操作应返回 `NXFS_ERR_SAFEPATH_FORBIDDEN`。

---

## 职责

一个**零依赖**的受限子集，只做五件事，且各自独立可测：

| 操作 | 实现要点 | 崩溃可能性 |
| :--- | :--- | :--- |
| 读扇区 | 带硬性超时 | 无 |
| 写扇区 | 带硬性超时 + 一次最快最小重试 | 无 |
| 校验和验证 | CRC32C（优先用 CPU 硬件指令，如 SSE4.2 `crc32`） | 无 |
| 主总账解析 | 固定偏移 + 固定结构体 + 校验和 | 无 |
| 引导文件表解析 | 固定偏移 + 固定结构体 | 无 |
| 内核文件读取 | 顺序读 + 固定缓冲区 | 无 |

### 五条禁令 → 具体做法

| 禁令 | 落地方式 |
| :--- | :--- |
| 零动态分配 | 所有缓冲区由调用方提供；**不链接分配器**（用 `-nostdlib` 类约束或静态检查保证） |
| 零阻塞 | 每次 I/O 带 `NXFS_SAFEPATH_IO_TIMEOUT_MS`；超时即返回错误，**不等待** |
| 零递归 | 迭代实现 + 下探前校验深度 ≤ `NXFS_SAFEPATH_MAX_DEPTH` |
| 零断言 | 无 `assert`；所有分支都有错误返回路径 |
| 零复杂状态机 | 状态存在调用方；唯一例外见下节 |

## 关键设计点

### 1. 扇区写入的两段式失败模型（本包最精细处）

> ⚠️ 本节已按 **API v1.0.1** 修正：快速重试成功**不**返回 NXFS_OK，
> 而是返回 `QUICK_RETRY_DONE`（负值但含义是"写已成功 + 声明重试"）。
> 修正说明见 `fs-api-design/兼容层适配报告.md` R-1。

```
首次写入成功
  └─→ 返回 NXFS_OK（quick_retry_done = 0）

首次写入失败
  └─→ out->quick_retry_done = 1        ← 声明"将进行一次快速重试"
      执行一次最快最小重试（无分配、无日志、无状态机，只做那一次扇区写）
        ├─ 成功 + 事件登记成功 ─→ 返回 QUICK_RETRY_DONE
        │     （quick_retry_succeeded=1, supplement_registered=1；
        │       写已成功——调用方不得重发同一写请求，见第 2 点）
        ├─ 成功 + 事件登记失败 ─→ 返回 EVENT_LOG_EXHAUSTED / APPEND_UNCERTAIN
        │     （写已成功，但存在未登记的完整性缺口；supplement_registered=0）
        └─ 失败 ─→ 返回终局写错误
                   TIMEOUT / INTEGRITY_UNCERTAIN /
                   DEVICE_WRITE_PROTECTED / CORRUPT（仅此情形写未生效）
```

**四条必须遵守的规则**（见 `10-公共约定.md` §4 纪律二）：

1. **防双写铁律**：除"两次均失败"外，写已生效——调用方在任何非 NXFS_OK 返回下**不得重发同一写请求**。
2. "声明重试"**必须是返回值的一部分**，不能只写日志——安全路径无复杂状态机，调用方是唯一能记住此事的人。
3. 快速重试**不得成为可关闭选项**。`allow_quick_retry` 为保留字段（必须传 1）。
4. 重试**仅一次**。第二次失败即终局。

### 2. 事件追加：唯一的"有状态"例外

`event_append` 是安全路径中**唯一**偏离"每次调用独立"的操作。必须实现，因为：

> 若由上层登记"重试成功但补充未做"，则存在"重试成功 → 上层登记前断电"的窗口，
> 该事实会**永久丢失**——而它恰恰是数据完整性缺口。

实现要求：

- 定长记录（`NXFS_SAFEPATH_EVENT_SIZE` = 64 B），追加写；
- **允许借用紧急保留空间**（缺口可见性优先于空间紧张）；
- 事件区（含借用的紧急空间）满 → `NXFS_ERR_SAFEPATH_EVENT_LOG_EXHAUSTED`（终局）；
- 追加本身失败 → `NXFS_ERR_SAFEPATH_APPEND_UNCERTAIN`（终局，**不可重试**，因为数据已写入但完整性不确定）；
- **绝不静默丢弃高优先事件**。

**高优先约定**：`kind & 1 == 1` 即高优先。故 `QUICK_RETRY_SUPPLEMENT_PENDING = 1`、
`APPEND_UNCERTAIN_PENDING = 3` 是高优先；`RESERVE_RECLAIM_PENDING = 6`、`DEFRAG_PENDING = 8` 不是。

### 3. 引导路径必须零恢复依赖

阶段一只有：**主总账 → 引导文件表 → 内核文件**。

绝不能依赖用户态恢复流程（重放、检查点、跨文件区分发都需要用户态）。因此：

- 总账校验和验证与副总账降级必须能在**纯固件环境、无分配器、无日志重放**下完成；
- 解析必须**固定偏移 + 固定结构体**，不得要求扫描或重建索引；
- `from_secondary` 字段显式表达"已从主总账降级到副总账"，使固件侧也能如实上报。

### 4. 与设计稿 §13.3 的代码量对应

保留为进度基线，实现时可对照：

| 模块 | 估算 |
| :--- | ---: |
| 主总账读取 + 校验 | ~200 行 |
| 引导文件表解析 | ~100 行 |
| 扇区读写（带超时） | ~300 行 |
| 内核文件读取 | ~200 行 |
| 错误处理 | ~200 行 |

> `ReadFile`/`pread`（Windows）或 POSIX `pread`。**同一套安全路径逻辑，两层薄包装**。

## 接口（`nxfs.h` 中本包负责的部分）

```c
typedef struct nxfs_safepath_v1 {
    uint32_t struct_size;
    nxfs_status_t (*sector_read)(const nxfs_safe_context_t*, const nxfs_safe_sector_options_t*, nxfs_safe_io_result_t*);
    nxfs_status_t (*sector_write)(const nxfs_safe_context_t*, const nxfs_safe_sector_options_t*, nxfs_safe_io_result_t*);
    int           (*verify_crc32c)(const uint8_t *buf, size_t len, uint32_t expected);
    nxfs_status_t (*ledger_parse)(const nxfs_safe_context_t*, nxfs_safe_ledger_result_t*);
    nxfs_status_t (*boot_table_parse)(const nxfs_safe_context_t*, nxfs_safe_boot_table_result_t*);
    nxfs_status_t (*kernel_read)(const nxfs_safe_context_t*, const nxfs_safe_boot_entry_t*, uint8_t*, size_t, nxfs_safe_io_result_t*);
    nxfs_status_t (*event_append)(const nxfs_safe_context_t*, const nxfs_safe_event_append_options_t*, nxfs_safe_event_append_result_t*);
} NXFS_ALIGN8 nxfs_safepath_v1_t;
```

**注意**：`nxfs_safe_sector_options_t` 的 `lba` 与 `count` 以**扇区**为单位（非簇）。
`nxfs_safe_ledger_result_t` 中的偏移以**簇号**为单位。转换责任在本包
（`cluster_size / 512` 的整数倍关系必须先断言）。

## 验收标准

| ID | 标准 | 验证方式 |
| :--- | :--- | :--- |
| `AC-20.1` | 七个入口各自可独立调用，互不依赖 | 单元测试逐个调用 |
| `AC-20.2` | 超时后**必然**返回错误，不重试、不阻塞超过 `100ms + 一次重试` | 注入延迟的错误设备 |
| `AC-20.3` | 首次失败 + 重试成功 → 返回 `QUICK_RETRY_DONE`（负值 = 写已成功），`quick_retry_done == 1 && quick_retry_succeeded == 1` | 注入首次失败、二次成功的设备 |
| `AC-20.4` | 快速重试成功后 `supplement_registered == 1` | 检查事件区确有对应记录 |
| `AC-20.5` | 快速重试失败时返回终局错误，且**不再重试**（调用计数 == 2） | 注入持续失败的设备 |
| `AC-20.6` | 深度超限返回 `SAFEPATH_DEPTH_EXCEEDED`，不递归 | 构造 17 层结构 |
| `AC-20.7` | 主总账校验和错误时自动降级到副总账，且 `from_secondary == 1` | 篡改主总账一个字节 |
| `AC-20.8` | 事件区满时借用紧急空间，置 `borrowed_emergency == 1` | 填满事件区 |
| `AC-20.9` | 事件追加失败返回 `APPEND_UNCERTAIN`，且**不重试** | 注入追加失败 |
| `AC-20.10` | **无动态分配**：链接期或静态检查可证明未引用分配器 | 符号表检查（`malloc`/`calloc`/`new` 均不出现） |

| `AC-20.12` | 头文件能被 C11 与 C++17 同时编译 | 两种编译器各编一次 |
| `AC-20.13` | 读扇区 CRC32C 与参考实现逐位一致（含空缓冲、非 4 字节对齐长度） | 与已知向量比对 |

## 常见坑（实现前先看，能省一轮返工）

1. **`struct_size` 是 48 不是 32**。`nxfs_envelope_t` 实际为 48 字节（编写期已用静态断言锁定）。
2. **`nxfs_subject_t` 是 40 字节**，不是 32。别按 32 做数组步长。
3. **`nxfs_ring_slot_t` 是 128 字节**，槽位总大小 4096。槽位大小必须能被槽位对齐整除，
   否则生产者/消费者错位——`verify_align.c` 里已有对应断言。
4. **`0x8E` 不要用**。它是 Linux LVM。用 `0x7F`。
5. **CRC32C 不是 CRC32**。多项式不同（Castagnoli，`0x1EDC6F41` 反射形式 `0x82F63B78`），
   用错会全盘校验失败。
6. **不要在安全路径里做路径解析**。它只认簇号与 LBA；路径解析属翻译层。
7. **`timeout_ms == 0` 表示用默认值**，不是"不超时"。
8. 扇区读写的 `buf` 容量必须 ≥ `count * 512`；**容量不足要返回 `BUFFER_TOO_SMALL`**，
   不要截断。
