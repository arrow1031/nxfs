# 差异化（按文件可选冗余，RAID5/6 级）· 工作量评估与设计草案

> 用户 2026-09-29 要求：**先评估工作量**；能今晚一起做完就做；**必须可选**（首选按文件 ✓，
> 退一步按盘开关 ✓，再退至少**格式化时可选** ✓）。本文件给出结论、依据与最小可行路径。

## 1. 结论（诚实）

**今晚不做** ✗。它触到**盘上格式**、**写入路径**、**读取重建路径**与**跨包（80/EFI/D0）同步**四处，
不是"小改动" ✓ 硬塞会在无人值守时引入不收敛的风险 ✗（且违背"不发明与文档冲突的格式"纪律 ✓）。

**评估**：以本项目的纪律（加性 + 有牙负对照 + 门禁 40/40 + 跨包同步）计，
安全可交付的版本 **≈ 2–4 个代理日**（取决于校验算法与重建路径的测试深度 ✓），分 3 批。

## 2. 为什么不是小改动（逐条）

| 面 | 要动什么 | 风险 |
| :--- | :--- | :--- |
| **盘上格式** | 文件/块层要能标识"该条带受保护"与校验块位置（`file_flags` 或 `block_flag` 扩展 + 版本/标志位） | 格式一动 ⇒ **80/EFI/D0 必须同步**，否则互不认账 ✗ |
| **写路径** | 写 N 个数据块时**顺带算并写**校验块；CoW 下整组重写（不像 RAID5 读-改-写那样贵 ✓） | 与"连续段分配"耦合（组内要连续才高效 ✓） |
| **读路径/重建** | 读到坏块（CRC 失败）时，用组内其它成员 + 校验**重建**并**如实上报重建事件** | 重建只在"其它成员可读"成立 ✓；重建后要不要回写修复需与自愈配套 ✓ |
| **剔除/回收** | 组内成员必须同生共死（释放一起释放 ✓） | 与包 70 的簇状态机、位图持久化强耦合 ✗ |
| **测试** | 需要**可控注入坏块**（改盘上字节 + 重封簇头 CRC ✓ 已有先例 ✓）来证明"能重建"与"不能重建时如实报错" | 负对照不可省 ✓ |

## 3. 最小可行路径（3 批，可选性从粗到细）

**批 A（最粗但最稳）**：**格式化时可选** ✓
- `d0_mkfs --redundancy stripe:N`（或 `--redundancy none|stripe8|stripe16` ✓）+ 卷级特性位 ✓；
- 卷内**所有非内部对象**按同一策略：每 N 个数据簇 + 1 校验簇（RAID5 级 ✓）；`N=8` ⇒ **12.5%** 开销 ✓；
- 重建：读路径在 CRC 失败时按组重建；`--verify` 报告"重建了几块" ✓。
- **可选性**：缺省 `none` ⇒ 行为与今天完全一致 ✓（HDD 默认不动 ✓）。

**批 B**：**按盘开关** ✓（读卷级特性位 ⇒ `stfs_volume_open` 暴露"该卷是否启用冗余" ✓，调用方只读感知 ✓）。

**批 C**：**按文件/目录开关** ✓（`file_flags` 一位 + 目录继承 ✓）⇒ 最终形态 ✓。

**批 D（可选）**：**双校验**（RAID6 级 ✓，`N` 数据 + 2 校验 ✓，任一 2 块可重建 ✓）+ 自愈回写 ✓。

## 4. 与既有优势的关系（为什么不冲突）

- **不替代**双总账（元数据 ✓）与 CRC（检出 ✓）、CoW（版本化 ✓）—— 是**叠加** ✓；
- **反而更强**：RAID5/6 需要**多块盘** ✓，本方案是**单盘内**的局部损坏重建 ✓ ⇒ 换了一条轴 ✓；
- 代价诚实：**空间 1/N 或 2/N** ✓ + **写放大上升**（校验块 ✓）⇒ 只对"重要文件/目录"开 ✓。
