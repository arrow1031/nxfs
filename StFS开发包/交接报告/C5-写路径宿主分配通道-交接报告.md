## 1. 缺口

- 分配器的唯一所有者是包 `70`；而实现侧的挂载上下文是**调用方提供内存**的（零动态分配纪律）⇒ 它没有地方安放「谁来分配/释放簇」与「时钟」。
- 后果：**经 API/装配面打开卷的消费者只能读、不能写**。工具侧能写，是因为它直接绑定了内部面。
- 性质：这是 **API 缺位置**，不是实现缺引擎——包 `40` 的 `stfs_meta_host_fns_t` 回调面与包 `70` 的有状态分配器**本已具备**，`cow.c` 已在调用、只是**未绑**。
- API 立场：**不接管分配策略**，只把**回调通道**交还调用方（与 v1.3.0 `ctx_storage` 的「存储交还调用方」同一手法）。

## 2. 改动

### 2.1 API（设计仓 · `stfs.h`，ABI 1.5 → 1.6，MINOR）

- 新增 `stfs_host_alloc_fns_t`：`struct_size` + `cookie` + `alloc_clusters` + `free_clusters` + `now_ns`。
- `stfs_volume_open_options_t` **尾部追加** `const stfs_host_alloc_fns_t *host_alloc`（80 → **88**）；既有字段偏移不变。
- **NULL ⇒ 只读挂载**（合法形态，非错误）；写路径如实返回 `STFS_ERR_NOT_SUPPORTED`；实现侧**绝不自建分配器**。
- 尾追加 ⇒ 按本仓变更边界表属 **MINOR**（函数指针表未动）。
- 计数同步：`51 结构体 / 51 错误码 / 59 操作码 / 66 接口函数指针 / 23 静态断言`。

### 2.2 05 装配层

- 可直测入口：`stfs_ea_host_alloc_install(ctx, fns, ctx_size)`，加三条转发 `ea_ha_alloc` / `ea_ha_free_clusters` / `ea_ha_now_ns`。
- 适配器落在调用方 `ctx_storage` **尾部**：**零全局、零分配**，**不碰 `40` 的冻结布局**。
- **fail-closed**：`struct_size` 不足 / 缺 `alloc` / 缺 `free` / `ctx_size` 装不下 ⇒ `STFS_ERR_INVALID_ARG`；**绝不静默降级成只读**。

## 5. 给设计者的待裁定项

### 5.1 `type` 已由二值变三值，设计稿 §3.4 需人类修订（本批**只建议、不改**）

- **现状冲突**：设计稿 §3.4 写「**1 byte = 普通/程序**」（二值）；实现侧 `type` **已是三值**：`0 = 未设置` / `1 = 普通` / `2 = 程序`。
- **为什么重要**：三值下「**未设置**」成为**显式状态**，与「普通」可区分（避免「零值即普通」的隐式约定）；但 §3.4 的字节描述与盘上实际取值已不一致。
- **建议（由人类裁定并修订 §3.4，本批不自行改设计稿）**：把 §3.4 的 `1 byte` 描述改为三值，并**显式写明 `0` 的语义**；同时裁定**旧镜像的 `0` 应按「未设置」还是「普通」解释**（这决定旧卷读入语义，须由人给出唯一答案）。
