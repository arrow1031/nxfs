### ⚠️ 最重要的一条术语纪律

**`STFS_SAFEPATH_MAX_DEPTH = 16` 是契约层的调用/结构深度，不是数据层数。**

### 与 `40` / `70` / `90` 的三方分工（**同一份文件夹日志里，谁的字节谁负责**）

三包都会碰到"文件夹日志"，但**各写各的字节、互不解释对方**——这条不写清，新流必然与 `70`/`90` 撞车：

| 结构 | 归谁 | 位置 | 说明 |
| :--- | :--- | :--- | :--- |
| 日志区**头簇**（自验证标识：文件夹 ID + 版本 + 校验和） | **本包（50）** | 每个日志区第 0 簇 | 自包含：不依赖其它结构即可验证自身身份与版本；布局冻结，只能版本号 + 尾部追加 |
| **父日志条目**（**9 B**：子文件夹偏移 4 + 长度 2 + 状态 1 + 类型 1 + 校验 1） | **本包（50）** | 父文件夹日志区的**条目区** | 日志树的**结构链接**（指向子日志区）；`INV-10` 按簇对齐 |
| `STFS_META_OBJ_FOLDER_LOG` 对象的**存在、指针、事务** | `40` | 元数据对象（连续簇） | 40 只搬对象、管表、换指针，**不解释载荷**（其 `FREEZE.md` 已就此裁定） |
| **目录项**（文件名 / 属性 / inode 映射等布局） | **`70` / `90`** | 同一日志区的**数据部分** | 与父日志条目**不是同一结构**，不得合并（见关键设计点 2） |

**推论**：50 实现"日志区 + 头簇 + 父日志条目 + 树遍历"，**不实现目录项语义**；
`70`/`90` 实现目录项，**不重写**头簇与父日志条目布局。两侧共处一份日志区时，
**以头簇自述的边界划分**（条目区 vs 数据区），任何一方都不靠对方解释自己的字节。
边界长度/偏移字段的**权威在 50 的头簇**（这是 §14.4 意义上的"规则所有者"）。

## 关键设计点

### 1. 物理偏移直寻（本设计的核心机制之一）

- 父文件夹日志记录子文件夹的**物理偏移（簇号）**。
- 每个日志区头部带**自验证标识**：文件夹 ID + 版本号 + 校验和。
- 恢复时**从根逐层向下，每层读一个头簇（4 KB）即可定位跳转**——不需要扫描。

**实现后果**：

- 头簇必须是**自包含**的：不依赖任何其他结构就能验证自身身份与版本。
- 头簇布局**一经冻结不可改**（只能版本号 + 尾部追加）。
- 偏移记录**按簇对齐**（`INV-10`）。
- 这使得"定位一个深层文件夹"的代价是 O(层数) 次读，而不是 O(日志大小) 次扫描。
  这是与"日志重放"完全不同的恢复模型——**直寻优先，重放兜底**。

### 2. 父日志条目结构（设计稿 §3.4，注意有校验字段）

| 字段 | 大小 | 内容 |
| :--- | ---: | :--- |
| 子文件夹偏移 | 4 B | 簇号 |
| 长度 | 2 B | 日志区大小 |
| 状态 | 1 B | 正常 / 迁移中 / 待回收 / **待变更** |
| 类型标记 | 1 B | 普通 / 程序 |
| 校验 | 1 B | 条目校验 |

**注意**：设计稿 §3.4 表头未列出"校验"，但表体有该行。实现按**表体**为准（共 **9 B**）。

与 `10-公共约定` §3 的"索引条目宽度 8 B"（4B 簇号 + 2B 长度 + 1B 状态 + 1B 校验）
**不是同一个结构**：后者是通用索引条目，前者是父日志条目（多一个类型标记）。
**两处都要实现，不要合并**——这是最容易搞混的地方。

`状态` 的第 4 个取值 **"待变更"** 是延迟升层的载体（见第 4 点）。

### 3. 日志区隔离（与坏道规避是同一件事）

设计稿 §3.5 与 §11.1 是**同一条设计**的两种表述：

- 每个子文件夹日志区按**独立 extent** 分配；
- 日志区之间预留 **≥ 1 簇隔离带**；
- 物理距离**尽量远**（外圈 / 中圈 / 内圈分布）；
- 恢复时**按物理区域分片扫描**。

**实现要求**：分配器必须接受"物理位置分散"作为约束，而不是只找最近空闲区。
这意味着日志区分配**不是**普通的首次适配——需要一个按物理区域（外/中/内圈）轮转的分配策略。

### 4. 升降层（延迟升层）

| 事件 | 动作 |
| :--- | :--- |
| 底层文件夹创建首个子文件夹 | 父日志标记 **"待变更"** |
| 首次在子文件夹中创建文件 | **落实升层**：分配中间层日志区 |
| 从未在子文件夹中创建文件 | 保持"待变更"，**不消耗额外空间** |

**降层**：所有子文件夹删除后，日志区头部格式标识改回"底层"。

**执行要点**：

- 升层是**主体身份变更** → 必须先冻结旧主体（`40` 提供），转换缓存，再启用新身份。
- 旧主体冻结后**拒绝新写入**，不得静默接受。
- 转换走**预算制**：窗口内能转多少转多少，转不了的登记待办，下个窗口处理。
- 转换**可中断续作**（`stfs_subject_map_t.cursor`）。
- 若"从未创建文件"，则**什么都不做**——不分配、不变更主体。这条"不做"同样重要，
  它是设计稿 §10.1"不消耗额外空间"的落地。

### 5. 检查点

| 项 | 值 |
| :--- | :--- |
| 间隔 | 30–60 min |
| 强制条件 | 日志区总量 > 分区容量 **1%**（判定在 `40`） |
| 推进方式 | 按树形层级**自上而下** |

**自上而下的原因**：上层记录下层的位置。若先回收下层而上层还指向旧位置，
中断后就会出现悬空引用。自上而下保证任何中断点上的树都是自洽的。

```c
typedef enum stfs_checkpoint_scope {
    STFS_CHECKPOINT_TREE_TOP_DOWN  = 0,  /* 默认 */
    STFS_CHECKPOINT_TOP_LAYER_ONLY = 1,
    STFS_CHECKPOINT_ALL            = 2
} stfs_checkpoint_scope_t;
```

### 6. 恢复层级与降级链

| 层级 | 位置 | 恢复速度 | 适用场景 |
| :--- | :--- | :--- | :--- |
| 主总账 | 分区头 | 毫秒级 | 正常挂载 |
| 副总账 | 分区中部 | 秒级 | 主总账损坏 |
| 碎片区备份 | 碎片区 | 30 min–1.5 h | 前两级都损坏 |
| 文件夹日志区 | 各文件夹内 | 中 | 按日志重放 |

**恢复时间目标**（设计稿 §9.2，实现时作为性能验收基线）：

| 场景 | 目标 |
| :--- | :--- |
| 正常挂载 | 毫秒级 |
| 主总账损坏，副总账恢复 | 秒级 |
| 断电后少量日志重放 | 10–60 秒 |
| 中等规模重放（检查点 30–60 min） | **1–3 分钟** |
| 大量文件夹同时修改 | 10–20 分钟 |
| 极端恢复（碎片备份） | 30 min–1.5 h |

**降级链的实现纪律**：每一级降级都必须**如实上报**（哪个源、为什么降级），
不得静默降级（`10-公共约定` §4 纪律三）。

### 7. 数据层与物理区域的分片扫描

"恢复时按物理区域分片扫描"是坏道规避的配套：某一物理区域整片损坏时，
只丢失落在该区域的日志，而不是全盘日志。因此：

- 日志区的**位置信息必须能在不读日志本身的前提下获得**（靠上层的父日志条目）；
- 分片扫描的**扫描单元是物理区域**，不是逻辑文件夹。

> 迁移中条目 → `RECOVERY_REQUIRED`（直寻不越过迁移窗口）、只读上下文写路径全拒、
> 非法簇大小 / 未知标志 / 缺缓冲 / 空指针各自的码。

### 实现期裁定事项（供后续批次与 API 侧参考）

1. **条目区的头段就在头簇里**（第 0 簇同时承载头记录前缀与条目区头段）。
   理由：设计稿 §3.2 要求"每层读一个头簇即可定位跳转"；若父条目另处一簇，
   定位一层要读两簇，`AC-50.1` 的 `d + 常数` 不成立。代价是头簇为前缀 + CRC 尾
   让出约 132 B（4 KiB 簇下约 3%）。**本包的头记录是"条目区/数据区边界"的权威**
   （§14.4 意义上的规则所有者），`70`/`90` 请调用本包导出的 inline 与接口，不要自己再推。
2. **父日志条目 = 9 B，且是"1 字节打包"的盘上结构**：它不跨 ABI 边界，故不受
   `10-公共约定` §8 的 `STFS_ALIGN8` 约束；反过来给它 `STFS_ALIGN8` 会让 sizeof 变 12，
   与设计稿 §3.4 的 9 字节直接矛盾。**加宽条目必须升 `STFS_JOURNAL_FORMAT_VERSION`**
   （`entry_stride` 是自描述字段，v1 只认 9；读到别的宽度返回 `NOT_SUPPORTED` 而非误读）。
3. **降级必须显式同意**（与包 40 的 `STFS_MOUNT_ALLOW_DOWNGRADE_SECONDARY` 同一取向）：
   `stfs_journal_ledger_probe()` 在"采用副副本但未同意"时返回 `LEDGER_PRIMARY_CORRUPT`
   （报告仍已填好），`stfs_journal_open()` 据此拒绝装载。**同意不改变事实**
   （`source` 仍是副、`degraded` 仍是 1）。
4. **"从未写过的溢出簇"按包 30 的语义初始化，但不洗白损坏**：读失败时再按"不看校验"读一遍，
   **全 0** 才认定为未写入，**非 0 且校验不符**判 `CORRUPT` 原样上报——绝不重算 CRC
   把损坏变成有效（与包 30 §7 的"整簇全 0 = 借这次写初始化"同一判据）。
5. **格式 v2 议题（记录在案，未实施）**：条目区越出 2 簇时的分段布局；
   按物理区域（外/中/内圈）轮转的分配策略（属 `journal_alloc.c`）；
   检查点/升降层执行与重放所需的落盘进度字段。

## 常见坑

1. **契约层深度（16）≠ 数据层数（3）**。见本包边界段的术语纪律。
2. **父日志条目 9 字节 ≠ 通用索引条目 8 字节**。两处都要有，别合并。
3. **检查点必须自上而下**。反序会在中断后留下悬空引用。
4. **"待变更"是合法状态且不消耗空间** —— 不要一看到子文件夹创建就落实升层。
5. **日志区分配要接受物理分散约束**，不能用简单首次适配。
6. **`basis_points` 是万分比整数**（0–10000，v1.0.1 前误名 permille），不是百分比、不是浮点。
7. **移交的世代号在移交完成时递增，不在越线时**。这是最容易实现错的一条。
8. **空窗口必须完全无操作**，否则每 30–60 分钟就来一次全量缓存失效。
9. **降级必须可见**：`from_secondary` 之类的字段要如实填。
