## 关键设计点

### 1. 总账字段（设计稿 §2.3）与实现约束

| 字段 | 实现约束 |
| :--- | :--- |
| 分区标识 | 文件系统类型 GUID、版本号、簇大小。GUID 见 `10-公共约定` §3 |
| 全局事务状态 | 当前事务 ID、检查点位置、日志区总量 |
| 跨文件区指针 | 起始簇号、大小、写入指针、检查点位置（跨文件区实现在 `60`） |
| 文件夹日志树根 | 根文件夹日志区偏移、摘要状态 |
| **引导文件表** | 内核文件 LBA、大小、校验和（**固定 4 条**） |
| 校验和 | 整个总账的 CRC32C |

**硬约束**：

- 总账必须能在 `20` 的**零分配、固定偏移**路径下解析。因此字段偏移与大小**一经冻结不可改**
  （只能靠 `version` + 尾部追加）。
- **引导文件表所指文件在可引导卷上豁免物理迁移**（`INV-6`）。这是卷级不变量：
  `defrag` 的 `allow_kernel_file_move` 在可引导卷上**被强制为 0**。
- 副总账不是镜像备份，而是**独立的第二份权威副本**：写入策略决定二者的更新顺序，
  恢复时以校验和通过的那份为准（`50` 包实现降级链）。

### 2. 事务的三种失败必须区分（本包最容易出错处）

见 `10-公共约定.md` §4 纪律一。实现要求：

```c
/* 提交路径必须能产生这三种返回值之一，且调用方据此走不同分支 */
STFS_ERR_TIMEOUT                 /* 数据未写入 → 可重试 */
STFS_ERR_CORRUPT                 /* 可能写了一半 → 靠 CRC32C 识别并丢弃 */
STFS_ERR_INTEGRITY_UNCERTAIN     /* 已写入但完整性不确定 → 不可重试 */
```

**`INTEGRITY_UNCERTAIN` 的正确处置**：不可重试（重试会制造第二次不确定），
必须靠 CRC32C 事后核验 + 降级链（主总账 → 副总账 → 碎片备份）。
它正是"主总账校验和不过 → 走副总账"这条路径的具体成因，因此**必须独立成码**。

### 3. CoW 与"缓存只缓存已提交事务的元数据"

- 任何未提交修改**对其他读者不可见**（`INV`：唯一可见性边界是事务提交）。
- 提交是原子点：提交前旧版本可读，提交后新版本可读，不存在"半新半旧"的可读状态。
- 提交后必须回传：
  - `commit_seq`（全局基准点，供缓存判断"我的视图基于哪个提交状态"）
  - `affected`（精确裁剪范围）

**两者必须同时返回**：只有前者会导致失效风暴，只有后者无法判断陈旧性。

### 4. 责任主体的世代号递增时机

| 事件 | 递增哪个主体的世代 |
| :--- | :--- |
| 文件数据/元数据变更 | 该 `FILE` 主体 |
| 目录内容变更 | 该 `FOLDER_LOG` 主体 |
| 类型标记变更 | 该 `PARENT_LOG_ENTRY` 主体 |
| 块空闲池/预留变更 | 相关 `EXTENT` 主体 |
| 挂载/卸载等整卷结构变更 | `VOLUME` 主体（**仅此场景可用**） |
| 升降层主体移交 | **目标**主体（移交完成时，不是越线时） |

**常见错误**：为了省事每次提交都递增 `VOLUME` 世代 —— 这会把"最小责任主体"退化成
全局失效，直接毁掉设计目标。

### 5. 升降层：冻结 + 预算制转换

升降层的触发判定在本包，执行在 `50`。本包必须提供：

- 主体进入 `FROZEN` 后**拒绝新写入**（返回 `STFS_ERR_SUBJECT_FROZEN`），**不得静默接受**；
- `stfs_subject_map_t`：`old` → `next` 的转换映射；无法转换时 `next` 的 `a`/`b`/`gen` 置 0
  表示"只能整体丢弃"；
- `cursor`：转换断点，支持**中断续作**（不要求从头来）。

### 6. 快照与子卷

- 快照为 CoW：创建时**不复制数据**，只冻结元数据视图。
- 可写快照与只读快照的差别仅在写入时的 CoW 目标；对外表现由 `writable` 标志表达。
- 快照树：`parent` 用于构建父子关系，便于批量销毁与空间核算。
- 子卷克隆：`FULL`（全量拷贝，设计稿 §8.1 的"迁入时天然紧凑"）与 `COW`（共享 extent）。

## 常见坑

1. **别用 `VOLUME` 主体做常规失效** —— 会把最小责任主体退化成全局失效。
2. **`struct_size` 语义**：`stfs_volume_open_options_t` 等结构体由调用方填成**自己编译时看到的大小**；
   实现只解释已知前缀字段，不要假设等于自己的 `sizeof`。
3. **`features_ignored` 必须回报**（`10-公共约定` §4 纪律三）。静默降级不允许。
4. **`impl_caps` 与 `vol_attrs` 不可混用**（`INV-7`）。
5. **快照不等于备份**：它同样在同一个卷上，卷级损坏会一起丢。不要对外宣称是备份。
6. **事务范围决定是否会进入跨文件区**：`MULTI_FILE` 可能走 `60` 的路径，延迟高于 `FILE`。
   这个语义差异必须在 API 上可见（已在 `stfs_txn_scope_t` 表达），不要在实现里抹平。
7. 检查点**判定**在本包（日志量核算），**执行**在 `50`。别在本包直接跑检查点。

### 实现期裁定事项（供后续包与 API 侧参考）

1. **总账扩展自成一记录（同区第 1、2 扇区，双缓冲）**，而不是接在 88 B 前缀之后：
   前缀 CRC32C 只覆盖 `[0, 84)`，追加字段会成为**不被任何校验和覆盖**的盲区。
   扩展带 `txn_id` / `cluster_size` / `root_log_cluster` 三个交叉字段与 v1 前缀绑定；
   双槽使"扩展已写、v1 未写"的半写窗口**自动回滚**（装载时按 v1 的 `txn_id` 挑槽），
   不需要恢复代码。
2. **降级可见性显式化**：包 20 的 `ledger_parse` 是自愈式降级（返回 `STFS_OK` +
   `from_secondary`）；本层把它显示为 `STFS_ERR_LEDGER_PRIMARY_CORRUPT`，并要求
   `STFS_MOUNT_ALLOW_DOWNGRADE_SECONDARY` 才允许降级挂载。**建议 `50`/`B0` 沿用同一取向**。
3. **簇空间只有一份推导**：本包不在总账里放第二份几何权威，只把总账的 `cluster_size`
   填进 `stfs_st_geometry_t` 并保持 `segment_count = 0`（交给包 30 推导），
   然后核对二者一致。**包 70 请沿用同一条事实约定**；可配置数据区起点属格式 v2 议题。
4. **簇号 0 是"无对象"哨兵**（主体表 `obj_cluster == 0`），故元数据分配从簇 1 起。
   包 70 的分配器若把簇 0 分给元数据对象，会与这条约定冲突——请一并遵守。
5. **包内接口比顶层 ABI 多一个卷句柄**（`txn_commit`/`txn_abort`）：ABI 只带 `txn_id`，
   按 id 反查上下文需要全局登记表，而那属未定的会话/并发模型（`10-公共约定` §10）
   且 `INV-3` 禁止分层内注册表。装配层（`80`/`A0`）补一张登记即可。
6. **`bitmap_needs_rescan` 契约的消费方式**：本包把它搬到 `stfs_meta_volume_status_t`
   并按 `STFS_META_OPEN_RESCAN_BITMAP` 在挂载期重扫；`bitmap_trusted == (needs_rescan == 0)`。
   **包 70 的分配路径必须引用同一条前提**（不得把"需要重扫"当成"没有坏道"）。
7. **旧版本簇只登记孤儿、不猜引用计数**：有活跃快照时把簇数计入 `orphan_clusters`
   （可观测），回收归包 70。
8. **自查纪律（沿用包 30 的三件事）**：① 新增对照用例（"分次做完 vs 一次做完"
   抓到转换游标 off-by-one 的**真实缺陷**）；② 变异测试 14 处定向缺陷 14/14 被对应
   AC 抓到；③ 把隐含契约显式化（簇号 0 哨兵、`needs_rescan` 前提）写进实现仓 README。
9. **降级可见性的两个观察面必须口径一致**（合练观察项 **O-1** 的裁定，由统筹方落笔）：
   `stfs_meta_ledger_view_t` 与 `stfs_meta_volume_status_t` 各有一个 `primary_corrupt`，
   它们**不是同一字段的两份拷贝**，而是同一事实的**两个观察面**：

   | 字段 | 回答什么 | 谁在用 |
   | :--- | :--- | :--- |
   | `ledger_view.primary_corrupt` | "**这份账**的主份能不能信"（数据来源层） | 只拿到视图的调用方（`50` 的恢复、`B0` 的只读诊断） |
   | `status.primary_corrupt` | "**这次挂载**是否发生过主份不可用"（挂载结果层） | 按挂载结果判断的调用方（`A0` 的挂载策略） |

   **不变量**：`from_secondary == 1` ⇒ `ledger_view.primary_corrupt == 1` **且**
   `status.primary_corrupt == 1`。出现"数据取自副份，而某个观察面说主份没坏"的组合即为缺陷——
   首次合练 J3 抓到的 O-1 正是这个组合（已修，`AC-40.10` 加 1 条断言钉住）。
   **允许** `secondary_differ == 1` 而 `primary_corrupt == 0`：那不是降级，而是"一份落后/超前"。
   见设计稿 §14.2 的同名约束。
